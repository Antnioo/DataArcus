Before an AI Builds Your Power BI Custom Visual: 4 Checks

Posted on October 23, 2026

Microsoft's October 2026 feature summary brought custom visuals to the Power BI Report Authoring skill, the agent skill that writes report files for you. The agent can now add a custom visual, bind it to your data, format it and validate it. It works with custom visuals already in the report, including ones imported from a file, and it can suggest an AppSource visual when Power BI's own visuals can't do the job. A public demo this month went further: one prompt, and the agent wrote a brand-new visual from scratch, with drill-down and tooltips.

That is impressive, and worth five minutes of checks before you build on it at work. A custom visual is not a format setting. It is a package of code, a .pbiviz file, and Power BI gives it the data it shows. Microsoft's own warning: "A Power BI custom visual could contain code with security or privacy risks. Make sure you trust the author and source before importing it to your report." When an agent writes the visual for you, there is no outside author to trust: the code is yours, and so are these four checks.

1. Can your organization use visuals from a file?

Your Fabric admin decides who can add visuals from AppSource or from a .pbiviz file, with the tenant setting Allow visuals created using the Power BI SDK. Microsoft's admin page says this setting "is disabled by default", and an admin can turn it on for the whole organization or only for some security groups. Without it, you can't add the visual in the Power BI service and your readers can't view it there, however good it is. Ask your admin before you spend an afternoon on one.

2. Is "certified visuals only" turned on?

A second setting, Add and use certified visuals only (block uncertified), goes further. With it on, "only certified Power BI visuals render in your organization's reports and dashboards. Power BI visuals from AppSource or files that aren't certified return an error message."

A visual written for your report can't be certified. Microsoft's custom visuals FAQ asks whether a certified visual has to be in the marketplace, and answers: "Yes. Private visuals aren't certified." Certification means publishing the visual on AppSource through Partner Center, then a review that, for a new visual, "can take up to four weeks". The requirements also rule out code an agent may write unless you tell it not to: no fetch or XMLHttpRequest, no innerHTML, no eval, no minified files.

The usual way in for a visual made in-house is an organizational visual: your admin adds the .pbiviz to the organizational visuals list in the admin portal, certified or not, "even if they contradict the tenant settings of your organization", and decides who can use it. It reaches Power BI Desktop automatically too. Someone has to own it after that: the admin uploads every new version again.

3. Your laptop is not the service

The admin settings above only cover the Power BI service. Microsoft says it plainly: "The UI tenant settings only affect the Power BI service." Power BI Desktop follows Windows group policy instead: EnableCustomVisuals and EnableUncertifiedVisuals, both on by default. So a visual can work perfectly in Desktop on your laptop and show an error once it is published. Microsoft's planning guidance recommends keeping the two aligned. Before you show a new visual to anyone, publish a test copy to the workspace your readers use and open it there.

4. What an uncertified visual can't do

Even when your admin allows it, a visual that isn't certified misses two things many teams rely on. Export to PowerPoint doesn't support custom visuals unless they are certified. And in email subscriptions, uncertified custom visuals "display an error symbol". The organizational route doesn't change this: Microsoft's page on organizational visuals says they "can't be exported to PowerPoint or displayed in emails" from subscriptions, and that only certified visuals imported directly from the marketplace support those features. If your managers read the report in a Monday email, the new visual reaches them as an error icon.

One more setting to know: Allow downloads from custom visuals lets a custom visual save its data to a file. It is "disabled by default" and separate from your other export settings.

When Power BI's own visuals are enough

Many requests for a new visual are things the core visuals already do. Sales by category and subcategory with drill-down is a bar chart with a hierarchy on its axis. A rich tooltip is a report page tooltip. Charts, cards, tables and slicers need no admin approval, work in PowerPoint exports and subscription emails, and Microsoft keeps them up to date. A prompt that starts with "Use Power BI's core visuals only, and tell me if one can't do this" saves you all four checks.

If you do need a custom visual, ask the agent to follow the certification rules anyway, and run Microsoft's own check on the package: pbiviz package --certification-audit (powerbi-visuals-tools 6.1.0 or later) looks for unsafe calls to fetch, XMLHttpRequest and eval. Then bring your admin the source code, not just the file.

Questions

Can a custom visual made by an AI agent be certified?

Not while it stays private. Microsoft certifies only visuals published on AppSource ("Private visuals aren't certified"), after a review that can take up to four weeks for a new visual. For a visual used inside one organization, the usual route is an organizational visual, added by the Fabric admin.

Why does my custom visual work in Power BI Desktop but show an error after publishing?

Desktop and the service follow different rules. The tenant settings (Allow visuals created using the Power BI SDK, and Add and use certified visuals only) apply to the Power BI service; Desktop follows Windows group policy. If your tenant blocks uncertified visuals, a visual from a file shows an error in the service until your admin adds it as an organizational visual.

Are uncertified Power BI visuals unsafe?

Not necessarily. Microsoft says uncertified visuals "aren't necessarily unsafe": some can't be certified because they call an outside service, like a map. Certification means Microsoft's tests checked that the visual doesn't access external services or resources. For a visual you or an agent wrote, the checking is yours.
