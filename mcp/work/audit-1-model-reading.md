## Reuse
- **tmdl-model.js: yes.** It is pure (`[{path, text}]` in, model.bim JSON out) and runs in the browser and in Node. Missing: a written output contract and an explicit `opts` instead of module state (A1-14).
- **pbip-bind readers: partly.** The functions are pure, but they sit in a 530-line picker/UI file (`renderPicker`). Their field shape is lossy (no `displayFolder`, `description`, `isKey`, `summarizeBy`), carries a hidden `expr` property, and has a `'string'` default (A1-6, A1-7). Missing: own module, lossless documented shape.
- **model.mjs: no.** `ROOT` comes from the environment at import, the messages are worded for the MCP, the writer's `taken` is mixed in, it re-exports other blocks, and it returns two shapes (A1-5, A1-9, A1-10). Missing: `loadModel(path, {root, limits})` → `{model, fields, relationships, reports, skipped}` with coded errors. The tool layer would then own wording and policy.

## Bias
- The limits are measured and documented (PBIT_LIMITS, MAX_DEPTH). No golden number moved in this block's history (B-25 is a different case).
- Tuned or unmeasured: the percent word list (A1-11); English-only instruction screens (A1-13). `MONEY` (model-health-tmdl.js:343) knows Gulf codes plus USD/EUR/GBP only, so a `"CAD" #,0` or `"INR"` format is not money. The search depths `depth < 3` (model.mjs:180) and `depth > 4` (:156) have no recorded reason.

## Seen, not in scope
- Website `fromFile`/`fromFolder` (pbip-bind.js:113, 135) call `JSON.parse` on a model.bim of any size, with no cap.
- `byName`'s `fs.readdirSync(full)` (model.mjs:180) is not wrapped: one unreadable subfolder fails the whole name search.
- `server.mjs:82` `DIVIDES_OR_AVERAGES` is a 4th DIVIDES regex (pbip-bind:153, model-health-tmdl:340).
