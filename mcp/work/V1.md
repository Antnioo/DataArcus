## CHANGELOG line
- V1 (B-194, prototype, not released): `vscode/`, a VS Code extension that registers the bundled DataArcus MCP server
  with VS Code's MCP support (stdio, the workspace folder as `DATAARCUS_ROOT`, no telemetry, no network of its own);
  `vscode/RESEARCH.md` on what VS Code supports and the Marketplace steps. Packaged locally only, never published.

## Decisions I made
- Bundled server (staged from this repo), not the `.mcpb`'s folder (Claude Desktop's, may be absent or moved) and
  not a download (no network of our own).
- VS Code's own runtime by default (documented in vscode.d.ts); `dataarcus.nodePath` (machine scope) for another.
- `extensionKind: ["workspace"]`: the server runs where the files are (remote windows not tested).
- Off in untrusted and virtual workspaces; `dataarcus.workingFolder` resource scope; empty root when no folder.
- `@vscode/vsce` 4.0.0 (14 Sep, Node 22+), `@vscode/test-electron` 3.1.0, exact pins, in `vscode/package.json` only.
- Not added to `mcp/package.json`'s test list: the brief keeps changes inside `vscode/`, and the mcp package must
  stay self-contained; the vscode suite prints its own `PASS  vscode  <N> checks`.
- Publisher id `dataarcus` (a placeholder until the owner creates the publisher), categories AI, Chat, Data Science,
  icon = the site's 192 px icon, licence = the repo's LICENSE.

## Seen, not in scope
- `approve_plan`'s form has `approve` with `default: false`; VS Code answers a skipped form (a new chat message while
  it is open, or `chat.autoReply`) as accept with the defaults, so the server reads "declined" and refuses the plan
  for good. Safe (never an approval) but surprising. Proposed fix (mcp/server.mjs): no default on `approve`, and an
  accept without `approve` treated as "closed" (approve later), not "declined".
- With `chat.mcp.access: registry` (an organisation's policy) VS Code never starts an extension's server; only a
  gallery entry would run. Said in the README.
- When `dataarcus.nodePath` is set, the extension host's `ELECTRON_RUN_AS_NODE=1` still reaches the server and its
  children (the browser launch, unused in VS Code): harmless for Node; noted.
- The server's start line goes to VS Code's Output channel with the working folder's full path (as in Claude's log).
- Publishing tokens (Azure DevOps PATs) retire on 1 Dec 2026: use the manual upload or Entra workload identity.
