## The problem (measured on the laptop, Desktop 2.159, release/0.3.0 222c239)
R3 (#76) sorted an Arabic waterfall Descending with the value axis at the right. Desktop: Dec is the first step at the
LEFT, the bars climb left to right to Jan, Total at the far right. Power BI accumulates a waterfall in sort order, left
to right, and has no setting to invert its category axis: a Descending sort reverses TIME, not the direction.

## Plan (option A)
1. Shared engine, `assets/js/visual-gallery.js` `rtlWaterfall(query, ctx)`: from a waterfall's query (one Category, one
   Y: a measure or a summed column; no Breakdown) and its order (the sort's column: Min of Month Number in Tooltips, or
   the category itself when it is a number or a date, or the model's sort-by column), build a `columnChart` (Power BI's
   stacked column chart):
   - report-level measures (reportExtensions.json, names kept free of the model's by the writer's `freeExt` /
     the twin's taken-names set): `Waterfall base: <m>`, `Waterfall rise: <m>`, `Waterfall fall: <m>`,
     `Waterfall rise below 0: <m>`, `Waterfall fall below 0: <m>`, `Waterfall running total: <m>`;
   - their DAX: `_e` = the measure over every category up to this one in the ORIGINAL left-to-right order
     (`CALCULATE ( <m>, REMOVEFILTERS ( <category> ), FILTER ( ALL ( <order> ), MAX ( <order>, _o ) = _o ) )`, `_o` =
     this category's order value), `_s = _e - _y`; base = the part under the step (between 0 and the nearer end), the
     rise/fall = the step's size, coloured; a step that crosses zero is drawn in two parts (above and below 0). Blank
     where the measure is blank. No comparison sign (MIN/MAX/SIGN), as the writer's other report measures;
   - Y = base, rise, fall, rise below 0, fall below 0 (stacked in that order); Tooltips = the order field (for the sort)
     and the running total; sort = the order Descending (the first period at the RIGHT);
   - formatting: base `fillTransparency` 100 (invisible); rise = the theme's good colour, fall = the bad colour (the
     colours a waterfall takes from the theme), a waterfall's own `sentimentColors` kept when it has them; labels on
     the rise and fall series only (`labels.showSeries` false on the others); legend off (no item for the base);
     value axis at the right (`switchAxisPosition`), the quiet gridline colour as before; no categoryAxis.invertAxis.
   - Not possible, said everywhere: a Total column (the category axis holds only the model's members; a report-level
     measure cannot add one): the total is the top of the last (leftmost) step and the running total is in every
     step's tooltip. The base cannot be left out of the default tooltip (Power BI has no per-series tooltip switch):
     hovering the empty space under a step shows it, named "Base" / «القاعدة».
   - Fallback (option B, per visual): a waterfall the measures can't express (a Breakdown, more than one category, a
     sort by the measure, a text category with no order column, a name with a control character): kept a waterfall,
     left to right in time, the value axis at the right, and said ("A waterfall reads left to right in Power BI: its
     order is not mirrored").
2. Writer (`assets/js/pbip-page.js`, gallery block): in a mirrored right-to-left report the waterfall slot is written
   by `rtlWaterfall` with the writer's `extMeasure`; `pbip-export.js` writes a measure's `formatString` (the measure's
   table format) with it. A note `waterfallRtl` in the result: what was written per chart (or why kept).
3. Twin (`assets/js/report-mirror.js` `mirrorVisual`, kind waterfall; `mcp/lib/arabic-twin.mjs`): the same builder;
   the measures go into the twin's own reportExtensions.json (copied from the original when it has one), names free of
   the model's and the report's; the model's sort-by column and column types from the model when it is read.
   KIND_WHAT.waterfall says exactly what is written.
4. Texts: create_report's notes, the twin's "mirrors" (KIND_WHAT), the plan (plan_layout's chart axes sentence where it
   names the waterfall) and the approval page (it shows the plan's notes) say what is written.
5. Tests first: `mcp/test-0.3.0-waterfall-rtl2.mjs` (in mcp/package.json's test list). Then the suites touched
   (waterfall-rtl R3, twin, gallery, 0.3-arabic-titles, a11y, check), the website suites of the engines touched, the
   full `npm test` once.
