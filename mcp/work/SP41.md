## Interfaces
- `check-redact.mjs` (pure): `scrub(message, reportDir)`, `maskValues(message)`, `rel(reportDir, file)`,
  `relOut(file)`, `cleanPath(file)`, `tidy(finding)`: a report's text in, what the answer may carry out. Every finding
  leaves check_report through tidy; every validator message through scrub; every schema message through maskValues.
- `check-schema.mjs` (fs, through the reading layer): `schemaCheck({ reportDir, files, big }) -> { checked, errors,
  findings, notChecked, big }` (findings raw, cleaned by check-redact; the files found too large that `big` did not
  hold); `pointer(instancePath)`; `SCHEMA_COMMIT`; `VALIDATOR_VERSION`. The compiled schemas and the schemas' words are
  a cache of mcp/schemas, built the first time they are needed (the only state; the same files give the same answer).
- `check-impact.mjs` (pure): `impactOf(finding) -> kind`; `knownGap(code, object, visualJson, caps?)`;
  `impactSummary(counts, ctx) -> sentence`; `validatorVerdict(kinds, lang)`; `openedLine`, `mayLookLine`; the facts
  `IMPACT`, `DESKTOP_OPENS_SOURCE`, `DESKTOP_DRAWS`, `DESKTOP_OPENED`, `VALIDATOR_GAPS`, `OPENED_FIX`, `CHECKS`; the
  readers `arr`, `litOf`, `plainObj`. Imports only the catalog and check-schema's VALIDATOR_VERSION.
- `check-report.mjs`: `checkReport(path, opts) -> { report, lang, validator, schemas, impact, findings, notChecked,
  counts, truncated, ... }`, `builtByOf`, `fixRoutesOf`, `rulesInput`; re-exports the names above that it exported.
- The import graph: check-report -> check-redact, check-schema, check-impact, check-language; check-schema ->
  check-redact; check-impact -> check-schema; check-language -> check-impact. Nothing imports check-report back.

## Decisions I made
- A third module, check-redact.mjs: the brief asks for all redaction in ONE shared boundary, and check-schema.mjs makes
  findings (rel, the schema message's mask). Left in check-report.mjs, the schema module would import it back (a new
  cycle) or keep a copy (D-1016-01). Its own commit before the schema move. The suspicious names' and the too-large
  files' paths now go through its cleanPath (the same expression, written once).
- schemaCheck no longer writes into check_report's lists (out, notChecked, sk.big): it returns them, and checkReport
  adds them where it did, in the same order (D-1103-11). Not exported from check-report.mjs (it never was).
- VALIDATOR_VERSION moved to check-schema.mjs (it reads the installed validator's package.json): check-impact.mjs stays
  pure and reads it there for the known gaps' sentence. CHECKS, the check groups, went to check-impact.mjs (the
  summary's default "what ran"); checkReport imports it.
- arr, litOf, plainObj moved with the validator's known gaps (VALIDATOR_GAPS reads them; SP20's lesson): check-language
  imports them from check-impact.mjs, check-report.mjs re-exports them.
- Source-reading tests follow the text to its new file: powerbi-2026-10 U1-6 reads `SCHEMA_COMMIT = '...'` in
  check-schema.mjs; the claims test's CHECK_SAID scans check-impact.mjs and check-schema.mjs too (the summary's
  sentences moved there; 12 more checks, no expected number changed); the mutation suite's 5 C-* entries point at
  `CI`. The texts naming SCHEMA_COMMIT's and VALIDATOR_GAPS' file (schemas/SOURCE.md, research/MICROSOFT-WATCH.md,
  scripts/microsoft-watch.mjs) name the new files.
- sp41 builds its inputs in a temp folder from fixtures/twin-project (no report folder committed); the fixture holds
  sha256 and counts only. The private text sits in a filter's name, a bookmark's name, a schema value and text boxes,
  not in page names or visual types, which check_report returns capped and cleaned by design.
