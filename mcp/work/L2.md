## What the lab proved (laptop, Desktop 2.158, 12-13 Oct; the brief)

## Decisions I made
- **Names** (the brief's): `slicerStyle: "dropdown" | "pills"`, `grid: "solid" | "dotted" | "none"`. One schema line
  each in `CREATE_REPORT_INPUTS` (plan_layout takes `REPORT_LOOK`'s definitions from there), both in `REPORT_LOOK`
  (pinned, filled from the plan, on the approval page) and in `LOOK_DEFAULTS` (`dropdown`, `solid`; B-03: an option left
  out takes the plan's value). L1 and D2 edit the same lists: one line each, nothing else moved.
- **Which fields become pills** (metadata only, never values): the number of values is known only for a field the picker
  already marks: two values (`two`: a Boolean, or an IF/SWITCH column of two texts), a quarter (`cal.rows` 4), or (new,
  `few`) a calculated column whose DAX is IF/SWITCH with 3-6 distinct quoted texts. Over-counting is possible: a SWITCH that
  compares with texts counts its tests too. Then the pills get empty columns, or the field stays a dropdown (see Seen,
  not in scope). 2-6 values: pills; anything else: the rounded dropdown, and the answer's `slicerStyle.slicers`
  says each slicer's style with why. Never a guess from a name.
- **Property names** from Microsoft's catalog (`@microsoft/powerbi-core-visual-schema` 0.1.3, the version mcp/package.json
  pins): visual type `advancedSlicerVisual` (role `Values`); `shapeCustomRectangle.tileShape` `"pill"` (a catalog value);
  `fillCustom.show` / `fillColor`; `value.fontColor` / `fontFamily` / `fontSize`; `outline.show` / `lineColor`;
  `layout.rowCount` 1 + `layout.columnCount` = the values (one row, so the right-to-left order is one sort). Gridlines:
  `valueAxis.gridlineStyle` `"dotted"` (catalog enum: solid, dashed, dotted, custom), `valueAxis.gridlineShow` false.
- **Selectors**: the catalog's instance selectors list the button slicer's state-keyed cards (default, hover, press,
  selected). As Desktop showed for buttons (mcp/CLAUDE.md): each card's `show` in its own entry with no selector, the
  look in `{ id: "default" }`, the selected pill's look in `{ id: "selected" }`; the shape and layout (not state-keyed)
  with no selector. Gridlines with no selector, as every axis entry the writer already writes (measured, round 1). Both
  ways are run through Microsoft's validator in the test (with and without the state selectors); the laptop confirms
  which one Desktop draws.
- **Colours**: calm fill = the accent mixed 90% into the card; outline the design's edge colour; the selected pill's
  fill the accent and its text the design's text or the card colour, whichever reads at 4.5:1 or better on the accent.
  Dotted grid colour: the quiet grid's (text mixed 85% into the card), also where the theme has its own.
- **Right to left**: the pills' query sorts by the field, Descending (one row, so the first value is at the right). The
  Arabic twin (`report-mirror.js`) flips that sort on a one-row button slicer it mirrors; a twin of an Arabic report
  needs none.
- **Axis label greys**: not built (the brief: out of the default, only where 4.5:1 holds; no option asked for it).
