## CHANGELOG line
- L3: `metricSwitcher` (2-5 of the model's measures, off by default): the report gets its own page "Metric" / «المؤشر»
  with one single-select slicer and a bar chart (by the main category) and a line chart (by month, when the month has an
  order) whose values come from a field parameter, so each chart switches between the measures and keeps each measure's
  own format; the titles follow the metric. The model is never changed: the field parameter and its title measure come
  as a TMDL script file next to the project (lineage tags, NAMEOF of each measure, labels escaped), to apply in TMDL
  view; until then only that page shows Power BI's error. Pinned by the plan, listed on the approval page;
  check_report knows field parameters and flags a title measure that reads the display column alone.

## Decisions I made
- Name `metricSwitcher`, 2-5 measures as Table[Measure]; in REPORT_LOOK (pinned, shown in reportLook), no default (off).
- Its own page "Metric" / «المؤشر», after the report's pages and before the tooltip pages; not the page that opens; no
  page button to it in the other pages' headers (Power BI's page tabs reach it); no phone layout for it.
- Charts: a bar chart by the bound bar category; a line chart by the bound month only when the month has an order the
  chart can use (own type, the model's sort-by, or a number column: timeAxisPlan own/model/number), else left out and said.
  No Top N and no gradient on these charts (both are by one measure; the measure switches).
- Model names stay English (table Metric, columns 'Metric Fields', 'Metric Order', measure 'Metric Title'); a taken name
  gives "Metric 2"...; the labels are the plan's display names for the measures (Arabic in an Arabic plan), else the
  measure's name. The title measure lives in the parameter table.
- Lineage tags: deterministic (sha256 of the model's print, the report name and the measures), so the exact artifact's
  bytes are stable.
- The reference check of the exact artifact runs against the model plus the script's own table (read back with
  tmdl-model.js): the page's fields must be what the script defines.
- Saved default selection: NOT written. The bundled schema types formatting properties as anything
  (`additionalProperties: {}`), so the validator passing proves nothing, and no Desktop run has shown the shape for a
  field parameter (display or fields column, nesting). Said in the plan/answer (savedSelection) and "For the laptop".
- X1's EN-AR copy: one Metric table serves both page sets; its labels are in the report's language it was planned in
  (an English report's twin shows English labels in the slicer). An Arabic label column is not built.
- check_report: a note (fieldParameters: which tables, inModel), never "can break"; FIELD_PARAMETER_TITLE (warning,
  a DataArcus rule) when a model measure reads the parameter's display column and none of its other columns.
