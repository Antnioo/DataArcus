## The interfaces (D-1103-11: one input, one output, no hidden state)
- `model-discovery.mjs` (imports node:fs, node:path, ./model-names.mjs; lists folders, never opens or reads a file,
  never follows a link): `walk(dir, depth?, links?)` -> files and folders, links left out (pushed to `links`);
  `byName(name, root, prefer?)` -> the one model folder or project folder of that name | throws MANY_MODELS_NAMED,
  NO_MODEL_NAMED; `noModelAt(path, root)` -> the NO_MODEL_AT error (returned); `modelFolders(full, links?)` -> the
  model folders at or under full; `nearestModel(dirs, root, path)` -> the nearest | throws MANY_MODELS; `ReadError`.
  It gives candidate paths, never authority: loadModel calls `realIn` on byName's and nearestModel's path before any
  stat or read, and reads through its own readCapped / zipParts. sp42 P2 pins it: no open, read, realpath or write in
  its source; within, realOf, underRoot, real, inside, readCapped, zipParts, zipDirectoryCheck, unzipNeeded,
  notThisModel, linkError, isLink defined in model.mjs and not there.
- `report-inventory.mjs` (imports ./read-report.mjs, ./visual-meaning.mjs, node:path; no fs): `inventory(src,
  reportName, opts?)` -> the inventory. `src` is the strict source `{ dirs(rel), files(rel), has(rel), json(rel), sk }`
  by report-relative paths; `json` throws read-report.mjs's TooBig or Linked for a file left unread (counted in sk),
  anything else for an unreadable file (listed). Also `refOf`, `keyOf`, `filterText`, `typeName`, `isCustom`,
  `customNameOf`, `isDecor`. From read-report.mjs it takes the screen and the source contract only: INSTRUCTION,
  LONG_TEXT, safeName, safeText, REPORT_LIMITS, TooBig, Linked. sp42 P3/P4 pin it; P5 loads each module first.

## Decisions I made
- ReadError moved with discovery (the map's "model discovery/errors"): discovery needs it and must not import
  model.mjs back; model.mjs imports it and re-exports it, so `instanceof M.ReadError` and every code are as before
  (reader-seen S15, fuzz). One direction: model.mjs -> model-discovery.mjs -> model-names.mjs.
- The folder route's model choice moved as two functions, modelFolders and nearestModel; the step between them (a
  linked model folder said through realIn, the empty folder's Notice, NO_MODEL_FOLDER) stays in loadModel: it is
  containment and wording, not discovery. nearestModel sorts a copy (nothing else read the sorted list).
- loadModel now also puts nearestModel's folder through realIn, as it already did byName's: one rule for every path
  discovery gives. The walk never follows a link and `full` was already checked, so for every input it passes (sp42
  unchanged); only a folder swapped for a link between the walk and the read would now be refused. Under Risky changes.
- notThisModel (reads definition.pbir through readCapped) and the TMDL and report-file walks stay in model.mjs: they
  read bytes. walk itself moved (listing); model.mjs imports it.
- The Microsoft catalog (VS, canSync, rolesOf, roleLabel) stays in read-report.mjs: the inventory does not use it, and
  report-answer.mjs and others import it from there. The inventory imports read-report.mjs's screen and source
  contract, and read-report.mjs imports the inventory: a cycle, as report-answer.mjs's (SP21); no module uses the
  other's bindings while loading (only `VT` from visual-meaning.mjs, not in the cycle). sp42 P5 loads each first.
- node:path stays in the inventory for `path.basename` on a theme's name (identical on Windows, where `\` splits too);
  it is no IO.
- Two guards read moved text: v029e's "readdirSafe" now reads lib/model-discovery.mjs; the mutation suite's
  R-model-tie points at model-discovery.mjs (MDI) and R-image-screen at report-inventory.mjs (RI), edit strings byte
  for byte as before. No expected number changed.
- M5 (links): on Windows the file links (model.bim, .pbit, dangling) need rights and are not made; there M5 checks the
  folder junction is refused (OUTSIDE_LINK) instead of the record. M6 seeds the change by wrapping `fs.fstatSync` (the
  second look sees another time, then another size): deterministic, no race.
- One case per working folder where a list could be cut at 12 in readdir order (M7, M8's too-deep name): a small
  working folder of its own, so every list is complete and sorted.
