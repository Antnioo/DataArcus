## What the code does today (a78c7f6)
- Charts with two or more measures on one value axis, found by reading the writers:
  1. The gallery's combo (`assets/js/visual-gallery.js`, D2): one shared axis (`valueAxis.secShow: false`) when
     `unitOf` gives both measures the same class: `percent`, `currency`, `count`. Two panels (two line charts) when
     the classes differ or one is not known. Gaps: "currency" is one class, so SAR next to AED shares an axis; no
     scale (thousands vs millions), no duration (minutes vs hours); nobody confirms the pair compares.
  2. The native copy of custom visuals (`mcp/lib/visual-meaning.mjs` nativeFor -> `assets/js/visual-replace.js`): an
     amount with a percentage becomes `lineClusteredColumnComboChart` with the percentage in `Y2` and NO `secShow`:
     Power BI's combo then draws the line on a SECOND axis by default (an automatic secondary axis). Several values
     in one role become one clustered chart: unrelated units on one axis, unconfirmed.
  3. The writer's own charts (`pbip-query.js` line, bar, column, donut, treemap, gauge) and small multiples carry ONE
     measure each: no group. The tooltip page's charts: one measure each. The redesign and the Arabic twin copy the
     user's own visuals as they are (not a proposal of ours): out of scope, said below.

## Decisions I made
- **One shared rule, a new engine** `assets/js/axis-units.js` (browser and Node, `DAAxisUnits`), used by the gallery
  and the native copy (and the website when it gets a combo). Metadata only: format strings and names (the helpers of
  `assets/js/field-meaning.js`: ISO 4217 list, currency signs), the DAX text only to name a percentage's denominator.
  - `identityOf(field)`: `{ dim, code, scale, known }`. dim: `currency` (code: the ISO code from the format, or a
    Gulf sign mapped to its code: د.إ AED, ر.س SAR, ر.ق QAR, د.ك KWD, د.ب BHD, ر.ع OMR, ج.م EGP; € EUR, £ GBP, ₹ INR;
    "$", "¥" and the named "Currency" are NOT mapped: no code, so not known), `percent`, `ratio` (× / "x"),
    `duration` (code: second/minute/hour/day/week/month/year, from the format's quoted unit or the name's words in
    English or Arabic), `count` (a count expression or a whole-number format over a counted column), `unit` (another
    quoted unit, normalised spelling), else unknown. scale: the format's trailing commas (`#,0,` thousands, `#,0,,`
    millions) or a quoted K/M/B/ألف/مليون; else 1.
  - Normalising = the same unit written differently gets one identity ("min", "mins", "minutes", "دقيقة" -> minute;
    "%" by format or the picker's pct -> percent). Nothing is converted: minutes and hours stay two units (no
    normalisation approved between them), no measure or format is changed, no exchange rate exists in the code.
  - `decide(measures, { confirmed })` -> `{ share, ask, groups, why: { en, ar }, labels }`:
    unknown identity on any -> separate; dims differ -> separate; codes differ (SAR/AED, minute/hour) -> separate;
    scales differ -> separate; same identity -> ask (a percent's question also names its denominator: the second
    argument of its DIVIDE, or "/", from the DAX: the same, different or not known); answered "comparable" -> share;
    answered "separate" -> separate. Unanswered -> separate (the default), with the question in the plan.
  - A confirmation is a record of the confirmation memory: `confirm-memory.js` gets an axis question
    `{ id: 'axis-share', obj: '[A]|[B]', axis: { measures } }` whose signature hashes both measures' DAX and format
    strings: a confirmation stops applying when either measure changes. Answers reuse the memory's two words:
    `intended` = comparable (one axis), `mistake` = separate.
- **MCP input `sharedAxes`** on plan_layout and create_report: `[{ measures: ['T[A]', 'T[B]'], answer: 'comparable' |
  'separate' }]`, only from the person's own answer; one more key of `REPORT_LOOK` (pinned with the plan, shown on
  the approval page, compared at the write). Turned into memory records (`Memory.record`) inside the server, so the
  engine sees one format. Not written to the answers file in this branch (that file is check_model_health's; see
  "Seen, not in scope").
- **The gallery's combo**: only for a pair `decide` lets share (same identity AND confirmed); otherwise two panels
  (D2's split), never a second axis. On a designed page a combo is placed only for such a pair. `secShow: false`
  stays written on every combo. The plan's gallery entry gets `whyAr`, and an `ask` when the pair awaits the person.
- **The native copy**: a custom visual whose values are two or more measures that may not share becomes panels: one
  native chart per group in the visual's box (side by side, or stacked when the box is taller than wide; the
  first keeps the visual's name, the others get `<name>_2`, `_3`), each a line chart over time or a column chart
  (a bar chart when the custom visual was bars), never a combo with Y2. A combo the person confirmed is written with
  `secShow: false` (one axis). The entry's `panels` and `whyAr` are pinned with the plan.
- **Unit labels**: a panel (and a confirmed combo) shows its unit as its value axis title (`valueAxis.showAxisTitle`,
  `titleText`: Microsoft's capabilities have both for line, column, bar and combo). The same token in both languages:
  `AED`, `%`, `×`; a duration's word in the report's language (minutes / دقائق); in Arabic the ISO code and any digits
  are wrapped in FSI ... PDI (U+2068 ... U+2069, as the picker already does) so they keep their own direction.
- Not changed: small multiples (one measure, one axis per panel by Power BI's own rule), the waterfall, the redesign's
  lossless copy and the twin (they copy the user's own visuals, a secondary axis the user made included).
