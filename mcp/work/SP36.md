## The interfaces
- **LocaleRoutes** (pure, UMD; `window.LocaleRoutes`, `require` in Node): `LOCALES` { en, ar }, each a descriptor
  `{ lang, dir, prefix, hasCopy(path) }` (language, direction from `RTL`, the copies' prefix, route availability);
  `LANGS`, `RTL`; `isArPath(pathname)`, `pagePath(pathname)`, `hasArCopy(path)` -> boolean; `pageKey(path)` -> the
  name of the page's translation global or null (the ordered route table); `arAddress(value, pageLink, base)` -> the
  address on an Arabic copy, or null to leave it; `pairUrl(href, here)` -> the other language's address or null.
- **LocaleCatalog** (pure, UMD): `load(common, page, current)` -> the dictionaries (a copy, page merged over it);
  `merge(translations, page)`, `deepMerge(target, source)` -> new objects, never the input changed;
  `text(translations, lang, path, warn)` -> the value or "[Missing: path]", `warn(message)` for a path through a text.
- **LocaleDom** (browser): `translate(doc, { text, lang, arCopy, base })`, `arLinks(root, base)`,
  `direction(lang, rtlLanguages)`, `meta(doc, text, lang)`: each changes the document it is given; no state.
- **The manager** keeps `detectLanguage` (the Arabic copy's address, then ?lang=, then the saved choice, then the
  browser's), `setLanguage` (storage, ?lang=, history.replaceState), the switcher, `toggleLanguage` (the other
  address when the page has one, saved first or carried in ?lang=), `init`; `pagePath`, `hasArCopy`, `arLinks`,
  `getPageTranslations`, `loadTranslations`, `mergeTranslations`, `deepMerge`, `getText`, `applyLanguage`,
  `updateDirection`, `updateMetaTags`, `pairUrl` are one-line calls into the modules. Load order on every page:
  routes, catalog, dom, manager (deferred, so they run in that order).

## Decisions I made
- The manager keeps every method name as a one-line delegate: `window.langManager` is what scripts/ar-pages.mjs and
  the tests use, and sp36 records the same methods on the base and after each move (no second way to call them).
- No top-level `const` in the manager (a classic script's top-level binding is global to every page script): the
  modules are read as `window.LocaleRoutes`, `window.LocaleCatalog`, `window.LocaleDom`.
- The direction code moved as it was: only `this.rtlLanguages`/`this.currentLang` became its two parameters (the
  diff of the body is those two lines). `RTL` is the one list; the manager's `rtlLanguages` is a copy of it and the
  descriptors' `dir` reads it. og:locale stays `lang === 'ar' ? 'ar_AE' : 'en_US'` in meta (no second copy of it).
- The route table is data (an ordered list, the home page's rule one marked entry); the module names the global, the
  manager reads `window[name]` (a missing file gives undefined, as before).
- The catalog returns new objects where the manager mutated `this.translations` in place: nothing outside keeps a
  reference to it (grep), and sp36 S14 records the merged dictionaries and that the common one is never changed.
- One stamp `20261104sp36` for the four changed files across the site (new against main; check-min agrees).
