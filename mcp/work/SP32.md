## The interfaces (D-1103-11)
- `MHWorkerClient.create({ Worker })` -> `{ run(buffer, fileName, onMessage), cancel() }`. Starts one worker at once
  (the page's load), keeps it between runs; a run while one is going terminates that worker and starts a new one; a
  failing worker is not kept. Out: `{ type: 'progress', step }`, `{ type: 'result', result }` (with the worker's
  `meta`), `{ type: 'error', code, message }` (`WORKER` blocked, `PARSE` failed, else the worker's code). No analytics,
  no DOM, no storage. It owns the worker's ?v= stamp (one place in the page's code).
- `MHFixPlan.plan({ result, ignored, lang, tmdl })` -> `{ broken, quick, tmdl, cleanup, scripts }`: pure (the same plan
  twice, its input unchanged; no page, clock, storage or worker); `scripts` holds every copy button's text by key.
- `MHView.create(app, host)` -> `{ render, loading, setStep, showError, score, rehashAnswers, cardText, text }`. In:
  `host.state` (the result, metadata only, and the person's selection: a plain object model-health.js owns; the view
  changes only the selection) and the page's services (`track`, `store`, `dismissed`, `saveIgnored`, `pick`, `sample`,
  `save`, `scoreCard`). Out: DOM inside #mhApp (and the Copied toast).

## Decisions I made
- **A third module, health-fix-plan.js** (not in the map): with the Fix plan's builders the view measured about 615
  lines; the builders are pure data and scripts (no DOM), so they are their own module and every file is under 600.
  Its commit sits between the client and the view; the order client, then view, is kept.
- **The worker's stamp stays `20261103sp15`:** the worker's .min.js is unchanged in this job; it changed since main
  (SP15, SP27) and sp15 is already not main's stamp (check-min passes). Bumping it only in the client would give one
  path two stamps (theme-generator.js, SP31's file, starts the same worker with sp15).
- **The score card stays in model-health.js** (as SP24 decided; sq7 reads its `arCount` and its counts there); its
  screen-reader list is drawn by the view (`cardText`), so model-health.js writes no HTML.
- **The state is one plain object** the page owns and hands to the view (no selection hidden in a module); the view's
  only instance values are the current plan's copy texts and the toast's timer.
- **Lifecycle through the language switch:** while a file is checked the page shows no drop zone; flipping the
  language re-renders it, and a second file dropped then cancels the first run. sp32's L1 and L2 use that real path.
- Session-dismissed questions and storage reach the view through `host` (it reads no storage itself; confirm-memory.js
  keeps its own, as before).
