## CHANGELOG line
- P7 (the owner, 21 Oct: "if English then the value in the pill LTR, if Arabic then RTL"): each pill's value centred
  (text wrap off), the header at the reading start, Arabic tiles from the right; every Arabic calendar label that mixes
  Arabic with digits («الربع 1», «2025 الربع 1», «السنة المالية 2025», «الربع المالي 1») written with its digit runs
  isolated and a right-to-left mark at the end the run reaches, so it reads in the right order inside a pill.

## Evidence (read before the plan)
- Microsoft's capabilities (`@microsoft/powerbi-core-visual-schema`, the pinned version: data/capabilities.json,
  advancedSlicerVisual): `value.horizontalAlignment` (formatting alignment), `value.textWrap` (bool), `label.
  horizontalAlignment`; `layout.orientation` is the arrangement (0/1/2: vertical, horizontal, grid), `layout.alignment`
  the tiles' block. No card or property sets a reading direction (searched: direction, rtl, reading, order, reverse,
  flow: none; `behavior.disabledItemsOrder` is something else). So the Arabic order stays the sort, Descending (L2,
  the twin's A1 check), as shipped.
- The header: the container title's alignment is the report's (pbip-export.js: right in a right-to-left report, left
  otherwise), already per language.
- The width check (C1 add-on, pillFits) measures the widest known value with text-measure.js, which gives the direction
  marks (U+200E/U+200F) and isolates (U+2066-U+2069) no width: isolating changes no width; centring changes none.
- C1's labels (assets/js/arabic-calendar.js) today: the year in «2025 الربع 1» and «السنة المالية 2025» in a
  left-to-right isolate (U+2066 ... U+2069), the quarter's digit in «الربع 1» and «الربع المالي 1» not isolated, no
  right-to-left mark. J18's rule (terminology.mjs isolateLatin): each run in a first-strong isolate (U+2068 ... U+2069),
  and a right-to-left mark (U+200F) beside a run at either end of the text.
