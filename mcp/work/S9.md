## Plan
**How the code moves.** Each top-level statement moves verbatim: its text, the comments above it and the comment on its
own last line, nothing re-typed. A small mover (kept out of the repo: an acorn walk of the file) lists every top-level
name each statement uses, so each new module gets exactly the imports it needs and each moved name its `export`; a tool's
`server.registerTool(...)` is wrapped in `export function register(server, ctx) { ... }` (two spaces more on each line,
never inside a template literal, so no description changes). Nothing is renamed; no function is changed or split.

**1. `mcp/server.mjs` (309,984 bytes) -> the entry, `mcp/tools/` and `mcp/lib/`.**
server.mjs keeps the server setup: the version (from package.json), the instructions (built from LIMITS), the
`McpServer`, `ctx`, one import and one `register...(server, ctx)` per tool in the order they were registered
(read_model, suggest_fields, check_model_health, create_report, generate_theme, check_report, read_report, plan_layout,
add_gulf_calendar, create_arabic_twin, approve_plan: tools/list's order), then prepareRoot and the transport. It stays
the entry (the manifest's, and the engine's build stages files by its import graph: every new file is reached from it).
`ctx = { LIMITS }`: the tools' limits, the same object the instructions are built from (suggest_fields and plan_layout
read it there).
