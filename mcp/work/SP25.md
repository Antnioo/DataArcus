## Summary
- **Approval:** the reviewer's brief "SP25" (4 Nov); the owner D-1016-01, D-1102-02, D-1103-10, D-1103-11. Backlog
  B-280, B-286 (the Codex split map, ## 13: "Extract svg-editor-store.js, svg-editor-pointer.js, then
  svg-editor-panels.js. Store owns command/undo transactions").
- **Base:** `feat/0.3.2-sp25` from `origin/integration/0.3.2` at fe4cc82. Push only this branch; never merge.
- **Scope (website only):** new `assets/js/svg-editor-store.js` (`window.SVGEditorStore`): the design, the selection,
  the undo and redo stacks (JSON snapshots, 100 deep), one-step-per-field-visit grouping and the commands. No DOM, no
  listeners, no canvas. svg-kpi-designer.js keeps the canvas, pointer, panels, DAX, import/export, tutorial and calls
  the store. Both designer pages load svg-editor-store.min.js before svg-kpi-designer.min.js.
- **The interface (commands in, state out, no hidden state):** `SVGEditorStore.create({ limit })` returns a store:
  - state out (getters, read only): `design` (the live design), `sel` (the selected layer, -1 the card),
    `canUndo`, `canRedo`;
  - commands in: `load(d)` (no history), `select(i)` (no history), `apply(fn)` (one undo step, then fn(design)),
    `checkpoint()` (one undo step for the change that follows: a drag's first move), `replace(d)` (one undo step; the
    design becomes d, selection -1), `editOnce()` (a field edit: one step per field visit), `newField()` (a new
    visit), `undo()`, `redo()` (true when something changed);
  - events out: `on('history', fn)` after a step is pushed; `on('restore', fn)` after undo or redo replaced the design.
  The drag object, zoom and guides stay with the pointer code (not editor state the history touches).
- **Characterisation suite `sp25` first (scripts/tests/sp25.mjs, shard 3), recorded on the base code:** Playwright,
  ?lang=en and ?lang=ar (1440 x 900): 10 scripted edit sessions (add layers, change properties by typing, drag with
  Alt (no snapping: fonts never move a number), resize by a handle, delete, keyboard moves and duplicate, undo, undo,
  redo, a 4-move drag that undoes in one step, an import, a bad import, an export, data links and rules, the card's
  fields). After every step: the layer list as shown, the selection, the Undo and Redo buttons, the selected layer,
  the saved design, the canvas SVG (layers and viewBox) and the DAX text; the export's file name and text. Recorded in
  `scripts/tests/fixtures/sp25-editor.json`; SP25_RECORD=1 records again (only on the base).
- **Before -> after (expected):** svg-kpi-designer.js 711 -> about 700 lines (the history block and the `design`/`sel`
  state leave it; each call site becomes a store call); svg-editor-store.js about 70 lines (new).
