### What the audit script found
1. **Regression, L3 (metric switcher) x the page filters (J17's Ramadan page)**: a report with `pageFilters` and
   `metricSwitcher` wrote its Metric page with no filter: on a "Ramadan 1446" report that page showed every date,
   while the tool says the filters hold "on every page". Cause: `addSwitch` (mcp/lib/metric-switcher.mjs) built its
   page.json without the report's filterConfig. FIXED (290cf2d): the Metric page copies the report's page filters,
   each under a name of its own. Came in with L3 (19fc9c4, merged in 45ed73b).
2. **Not the wave (on release/0.3.0 already)**: add_gulf_calendar's plan and approval page named
   "<model> - add Gulf calendar.tmdl" when a different calendar script of that name was there, and the click wrote
   "... 2.tmdl". Cause: the plan's namer (server.mjs) never looked at the folder. FIXED (9e97159): the plan asks
   writeScript for the name it would write, without writing.
3. The health fixture's own report has no `.platform` (validator PBIR_PLATFORM_MISSING, 2 errors, check_report 1 "can
   break"); its twin copies the report as it is and has the same 2. Fixture made by hand; not a writer bug. Not fixed.
4. My check's mistakes, corrected in the script, not the code: statusIcons with the person's thresholds writes no
   script (by design, L5); the second separate twin needs the first one renamed (the twin never writes over a file).
