## The slot shapes A2-3's fitSlots will need (for builder 11; the place is left free in the engine)
- `E.computeSlots(layout, lang, opt)`: on the 720 grid, `{ kind, role: { en, ar }, x, y, w, h, index, rail? }` (`index`:
  the slot's place among its kind, KPI 1 is 0; `rail`: the filter panel). `opt`: `{ logoRatio, tableFields }`.
- `E.projectPages(layout, lang, { second, panel, logoRatio, tableFields, maxKpis })`: per page `{ layout, name, page { w, h },
  slots, panel }`, each slot in page units `{ kind, title, rail, x, y, w, h }` (no `index` yet: adding it moves the
  project-pages fixture). `layout` is the page's own (small-page fitted, KPI-capped): the background PNG is drawn from it.
- `planLayout` (design.mjs): `slots` `{ role, kind, visual, x, y, w, h }` in page units, and `forAuthoring`
  `{ role, kind, position { x, y, z, width, height, tabOrder } }` sorted in reading order. A `fitSlots` must run before
  `forAuthoring` is made, so z and tabOrder follow the fitted slots.
- A pure `fitSlots(slots, { dropKinds, railItems, headerRows })` would take and return the `projectPages` slot shape (page
  units); the writer's `absorb`/`dropLines` (`pbip-export.js`) and the website's PNG replay (`theme-generator.js`
  `pngBlob(..., P.dropLines)`) are what it replaces. `mcp/lib/slots.mjs` and design.mjs's `absorb` import (now straight
  from the writer, not through model.mjs) go with it.
