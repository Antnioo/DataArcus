## The one-line form and the limits
`FAIL script=<repo-relative file> check="<first failing check, 160 chars>" cause=<cause> os=<linux|windows|macos>
shard=<k/N or ->`, printed right under the suite's result line (ci-sum takes it from there); then at most 4 KB of that
script's detail (its "  - " problem lines; for a crash, timeout or no result line, the end of its output), 16 KB a run,
each line cut at 300 characters, "N more lines not shown (full log: mcp/.test-logs/<file>.log)". Paths: the repo's
relative, the temp folder `<tmp>`, homes `~`. Causes: checks-failed, timeout, crash, no-result-line, duplicate-suite,
unexpected-skip, zero-checks, exit-nonzero, wrong-name; ci-sum adds missing-suite, unknown-suite, missing-shard, g13.

## Decisions I made
1. The adapter lives in `mcp/test-results.mjs` (a helper in `ignored`), not in `scripts/`: the runner is in `mcp/` and
   the MCP stays self-contained; the scripts import it from there, as they already imported `mcp/run-tests.mjs`.
2. Each suite gets its result `name` in tests.json, and test.mjs `sharded: true`: identities need the name a file prints,
   one source; a new suite's registered name is checked statically (check-result-lines) and at run time (`wrong-name`).
3. Every CI shard (1-4 too) runs through `npm test`: `DA_SHARD=k/N`, k >= 1, runs only the sharded suite, so test.mjs's
   failures get the same one line and caps; the full output per suite in `ci-logs/mcp-shard-<k>-full/` (the artifact).
   The console log stays ci-sum's input.
4. A per-suite limit under each job's: 780 s on Linux (job 15 min), 2,100 s on Windows and macOS (40); 2,700 s locally.
   A hung suite then fails as `timeout`, named, before the job is cancelled unnamed. The process tree is killed
   (a process group on Linux and macOS, `taskkill /T` on Windows).
5. `--verbose` keeps the old streaming; the default console shows result lines only. `mcp/.test-logs/` is git-ignored.
6. "No data values": the suites run on the repo's synthetic fixtures only; the detail is scrubbed of paths and cut per
   line, not parsed for values (a value filter would hide the failing check itself).
7. `--affected`: a suite file picks itself; `none` (notes, docs no suite reads, verified by grep); `everything` (the
   brief's safety paths, the server, the harness, fixtures, `mcp/*.md`, which several areas' claims checks read); areas
   by path; anything else, every suite. test.mjs (core) is picked only by its own paths: its parts cover every area,
   and the final gate runs it. Refused when `CI` or `GITHUB_ACTIONS` is set.
8. The website's zero-checks rule is not added to run-all (only the MCP's runner has it): I did not measure every
   website suite's count here (see "Seen").
9. WORK.md left to the reviewer's merge (this note holds A2's state); the workflow's new step is placed away from Q1's
   lint step and coverage job to merge cleanly.
