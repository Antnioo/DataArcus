## Decisions I made
- The parsers are handed over as an explicit argument, `readers` ({ fromTmsl, relsOfTmsl, clean, tmdl }), built once
  in pbip-bind.js: model-import-browser.js never requires pbip-bind (no cycle) and holds no copy of a parser. `tmdl`
  (tmdl-model.js) stays found by pbip-bind as before, so test-0.2.9e's A1-8 source check still reads it there.
- `decodeText` moved (only the input used it); `clean` stays in pbip-bind (it is the catalog's rule, applied to the
  answer). `LIMITS` moved with its comment tying it to mcp/lib/model.mjs PBIT_LIMITS (one place on the website side;
  the worker keeps its own copy as before, read-only for this job). M2 checks the values equal PBIT_LIMITS'.
- pbip-bind finds the new file lazily (`require` in Node, `window.DAModelImport` in the browser, at call time), as SP8
  did for the picker: the MCP never calls fromFolder/fromFile (checked), so no MCP file loads it.
- The MCP suite runs the Model Health Check's real worker source in a Node vm (its importScripts read the engines'
  sources), so a .pbit goes through the same unzip as on the page. Sizes over the limits are the size the file says
  (the refusal is decided on it before any byte is read); the website suite uses a sparse 64 MB + 1 file.
- The website suite sorts a chosen folder's files by path (SP8's lesson: the file system's order differs on CI).
- New stamps: model-import-browser and pbip-bind.min.js `20261103sp14` (theme-generator.js's loadBind), and
  theme-generator.min.js `20261103sp14` on both English pages (the Arabic copy rendered again).
