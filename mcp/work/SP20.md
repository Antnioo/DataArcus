## Decisions I made
- litOf, plainObj and arr are shared with the rest of check-report.mjs (VALIDATOR_GAPS, builtByOf, the rules): they
  stay there, gain `export`, and check-language.mjs imports them. The two modules import each other; that is safe
  because neither calls the other's functions while loading (checked: importing check-language.mjs first, then
  check-report.mjs, then arabic-lens.mjs and native-copy.mjs). None of the mutation targets is on those lines.
- langOfTexts is exported by check-language.mjs (checkReport reads the report's own language with it) but not
  re-exported by check-report.mjs: it never was exported. The letter tables stay private.
- pageLanguagesOut (what the answer says) stays in check-report.mjs: it shapes the answer (safeName, the 60 cap), the
  answer code, not the language reading.
- The suite builds its reports in a temp folder instead of committing 12 report folders: the fixture holds only the
  recorded languages (page ids and codes, no text) and the answers' sha256. Page names are not checked by X1: check_report
  returns them capped and cleaned by design.
- sp20 sits in area checker; check-language.mjs added to tests.json's checker area map beside check-report.mjs.
