## CHANGELOG line
- plan_layout and create_report write Power BI's waterfall, combo (line and clustered column) and small multiples when
  the user asks (a slot kind, or `gallery`), where the fields fit; a combo of two measures in different units is two

## The problem (laptop proof of 0.3.0-rc.2, Desktop 2.159)
1. plan_layout refuses a waterfall slot (the slot kinds enum is `VISUAL_KINDS`, without the gallery kinds).
2. plan_layout with `gallery: true` answers line, bar, bar, table: zod strips the unknown key, nothing reads it.
3. create_report never passes `gallery` to `Pbip.build` (server.mjs), so no tool can write the three visuals, though the
   engine (`assets/js/visual-gallery.js`, #61) writes them when called directly.
4. A report written with `gallery: true` was dark in English. Cause found: the direct calls (the gallery suites' own
   `build` helper, and the laptop's direct script modelled on it) start from `E.fresh()`, the website's DataArcus
   preset, which is dark. The writer never changes a theme; the MCP's designs start from Corporate (light,
   `design.mjs withDefaults`). Through the tools the gallery report gets the plan's theme: tested (TH below).
5. Direct Arabic gallery titles got "(2)" and "(3)". Cause found: `pbip-page.js` tells same-titled charts apart with
   the story titles' `alternate` (#57), but a gallery visual is written with no story entry in `fitted`, so the
   duplicate pass falls back to numbering. Fix in the shared writer: a gallery visual gets its story entry (its measure
   and axis as its title says them); where no story form is left (an Arabic report on English names, where #57 adds no
   English word), the kind's own Arabic word as a tail, as the table's «: التفاصيل» (R2).

## Decisions I made
- **Names.** The tools' kinds: `combo`, `waterfall`, `smallMultiples` (the brief's). The engine keeps its `multiples`;
  the server maps `smallMultiples` -> `multiples` at its edge, and names it `smallMultiples` in every answer.
- **Default: never silent.** A gallery kind is used only when asked: a hand-placed slot's kind, or the new input
  `gallery` on plan_layout / create_report: `true` (every kind whose fields fit) or a list of kinds. Left out: no
  gallery kind, the plan exactly as before. `gallery` is one more key of `REPORT_LOOK` (pinned with the plan, filled
  from it, shown on the approval page), and one schema line in `CREATE_REPORT_INPUTS` (plan_layout takes it from
  there). The slot kinds enum is `VISUAL_KINDS` + the three: one line.
- **Which designed slot** (a layout from the design engine): combo takes the first line chart (the trend); waterfall
  the first column chart, else the trend when combo does not take it; small multiples the next column chart, else the
  first bar chart. One shared function, `visual-gallery.js assign(slots, ask)`, used by create_report, the plan's lint
  and its preview, so they all see the same page.
- **A kind that does not fit** goes back to the slot's own kind (not the gallery's generic fallback: a small-multiples
  slot that was a bar chart stays a bar chart), and the plan says why (the writer's rule, `gallery[].why`).
- **Combo units (outside audit C13).** Combo only when both measures' units are known and the same (currency,
  percent, count: `unitOf`, metadata only). Different units, or a unit not known: two panels, side by side (stacked
  when the box is taller than wide), each a line chart of one measure over the same axis, the first at the reading
  start; the plan says "two panels" and why. Never `valueAxis.secShow: true`. The combo's line is the KPI measure with
  the columns' unit first (before: the percent first). This is a change in the shared engine on purpose.
- **Small multiples' second category**: the plan's `category` (the bar chart's), else the picker's bar category; the
  engine's rules decide (at most 9 members, no id/code/name, not time). "City" added to the engine's many-members words
  (a panel per city is never few), as the picker's own `manyValued`.
- **Preview**: the approval page's preview draws them with the renderer's placeholders: a waterfall and small multiples
  as columns, a combo as a line (`page-preview.js` already maps the three types). Said in the plan.
- **Arabic and right to left**: the writer's own mirror (D1 owns the waterfall's writer; not touched here); the Arabic
  twin's `report-mirror.js` already knows all three types (R3); tested end to end.
- Not touched: the waterfall's writer (D1), line-chart defaults (L1), look options (L2).
