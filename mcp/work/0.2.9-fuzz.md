# 0.2.9 fuzz testing: the readers of user files (cloud builder 10, 11 Oct; branch `fix/0.2.9-design`)

The owner's practice (11 Oct): fuzz everything that reads files people give DataArcus, before the beta on his old
dashboards. The test is `mcp/test-fuzz.mjs` (a test, not product code), in `npm test`: 300 cases a group, about 10 s;
`FUZZ_LONG=1` runs 5,000; every case is reproduced with `FUZZ_SEED=<s> FUZZ_CASE=<k> node test-fuzz.mjs`
(`FUZZ_TRACE=1` names each target as it runs).

**Targets:** read_report (inventory, text and JSON, from disk and from memory), check_report (every check, lint
included), plan_layout's lint, the model loader (model.bim, TMDL, .pbit) and read_model's answer, the TMDL reader, and
the Arabic twin's plan. **Inputs:** the made-up twin-project fixture (PBIR report and model.bim), a made-up TMDL model,
and a .pbit made from the model, mutated: null or missing fields, wrong types, huge strings, deep nesting, control,
format, Arabic and RTL characters, duplicate visual ids, odd folder names, a link out of the working folder, empty
files, truncated JSON, a truncated zip. **Properties (never weakened):** P1 no crash (a target answers, or refuses with
an error it throws on purpose; a TypeError, RangeError, SyntaxError, a stack overflow or more than 10 s is a finding);
P2 every answer within 40,000 characters; P3 no planted instruction text in an answer; P4 no raw control or format
character in an answer.

Every finding below is in the test's KNOWN lists with its owner and id: skipped while it still fails (counted and named
in the PASS line), its first case always run, so it turns on when the fix lands (the run then says "not seen: move it
out of KNOWN"). Nothing here was fixed: each is for the block's owner. "On the reader merge" is a scratch merge of
`origin/fix/0.2.9-reader` into this branch (never pushed), run with the same seed: what builder 6's open branch already
changes.

Owners and what each finding is:
- **F-R1, F-R2 (builder 6, reading):** `read-report.mjs` trusts the shape of the JSON: a `pageOrder`, `textRuns` or
  `paragraphs` that is not an array (F-R1) and a null projection, filter or text run (F-R2) throw. A5-2's class: one
  shape test at the reading block's entry (arrays are arrays, entries are objects) closes all of them.
- **F-M1 (builder 6, the TMDL reader `tmdl-model.js`):** a truncated or mis-indented TMDL file makes `parse` read a
  node that isn't there (:75 `props`, :94 `children`): the model loader throws with it.
- **F-M2 (builder 6, the model loader):** a model.bim or .pbit whose `tables`, `columns`, `measures` or `relationships`
  is not an array, or holds null, crashes in the field picker's catalog (`pbip-bind.js` :76-80, :302), which the
  loader calls; the check belongs where the loader takes the model in.
- **F-C1 (builder 7, checks):** `check-report.mjs`'s own reader (null report.json, page.json or bookmark; text runs not
  an array). Gone on the reader merge, where check_report reads through the reading block (then F-R1/F-R2 apply).
- **F-C2 (builder 7, checks):** `report-rules.js`: a sort list that is not an array or null (:175-176), and the `in`
  operator on a string or number (:111).
- **F-T1, F-T2, F-T3 (builder 9, twin):** `report-mirror.js` writes into and reads from the visual's JSON without
  checking its shape: a string or number where an object is (F-T1, "Cannot create property"), a null entry or a list
  that isn't an array (F-T2), and `clone` parsing `undefined` (F-T3, :27).
- **F-T4 (builder 9, twin):** `arabic-twin.mjs`'s own reader: `pageOrder` not an array (:82).
- **F-W1 (builder 11, the report writer):** above. Not on the reviewer's list of blocks: the hang is in the writer,
  reached through plan_layout's lint and create_report.

## How to turn one on
Fix it, run `FUZZ_SEED=20261011 FUZZ_CASE=<k> node test-fuzz.mjs` (seed 7 for F-W1), then the long run; when the
bounded run prints "known findings not seen in this run: <id>", delete that entry from KNOWN, KNOWN_PROPS or KNOWN_SLOW
in `mcp/test-fuzz.mjs`. Never widen an entry to make a new failure pass: a new one is a new finding.
