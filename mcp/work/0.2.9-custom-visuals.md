## Step A: `mcp/lib/visual-meaning.mjs`
`meaningOf(visual, { typeOf })` -> `{ kind, native, drill, series, confidence, why, htmlNeeded, roles, lost }`.
- Input: a visual as the reading block's inventory gives it (`{ type, fields: { Role: [field] } }`); the model's data
  types come from the caller (`typeOf(field)`), since report files carry none.
- Decides by (1) the fields' shapes: column or value per role (an aggregation of a column is a value), date type or a
  date-hierarchy level (never a column's name), several columns in a category = drill levels in order; (2) role names
  matched word by word against `ROLE_WORDS` (one table, easy to adjust: "ColumnValues" -> column, values); (3) a weak
  hint from the id's words (`FAMILY_HINTS`, 18 entries), used only when the fields can show that kind and said to be
  set aside when they can't.
- `roles` are the native visual's own role names with the report's fields (Category, Y, Y2, Series, Breakdown, X,
  Size, Rows, Columns, Values, Data, TargetValue, MinValue, MaxValue, Indicator, TrendLine, Goal, Tooltips); network
  gets Source, Target, Weight for Step D. `lost` says what the native visual doesn't carry (the custom drill's animation,
  a series dropped beside several values, the combo's line choice, the custom look).
- `why` and `lost` are written from role classes and counts only: no role, table, column or measure name (untrusted)
  reaches them (check 19).
- A Power BI visual keeps its own type, high confidence, nothing lost.

**Tests:** new `mcp/test-0.2.9v.mjs` (pure, no server; 30 checks on 26 made-up visual.json files in PBIR format, read
through `inventory(memorySource(...))`, made-up retail/HR/logistics fields and made-up ids). Red before: the module
did not exist (the load check failed, nothing else ran); green after: **30 of 30**. Wired into `test.mjs`.

### Open questions (for the owner's laptop, read-only, text only)
1. **The real role names** of the custom visuals in his reports: for each custom visual, its `visualType` id and the
   role names under `visual.query.queryState` (names only, never field names or data). If a name is not in
   `ROLE_WORDS`, add its word there (one line) and a test with a made-up visual using it. Until then a role with an
   unknown name is decided by its fields' shape (a column role: category, a value role: values) with low confidence.
2. **The id format**: the hint strips a trailing 32-character code; if the ids are written otherwise (a prefix, an
   underscore), the words still split at case changes and other characters.
3. **Combo charts that keep all values in one role**: which values draw as lines lives in the custom visual's format
   (`objects`), not its roles. The module takes the first value as columns and the rest as lines and says so in
   `lost`; if the format names it plainly, a later step may read it (format names, not data).
4. **Date hierarchy levels**: Power BI's auto date hierarchy levels are read as English names (Year, Quarter, Month,
   Day); a Desktop in another language may name them otherwise.
