## Decisions I made
- **three.js stays 0.160.0, and the bloom and focus passes are written in build-helix.js.** The Today app uses 0.186.1
  with EffectComposer. From 0.161 three ships modules only, and its passes are modules that import "three" by name: on
  this site that needs an import map, an inline script in the policy and a hash for every module file, which the site's
  one rule (one classic file from jsDelivr, pinned in package.json, with its integrity hash, `scripts/cdn.mjs`) cannot
  check. So the page keeps the file it loaded before, and the same look is drawn from three's own parts: a bright
  pass, two blurs (a near and a wide glow), a focus blur by depth, shadows, the three tiers. No new address, no change
  to the policy, the pin or H4.
- **The helix draws what the page read before, not only usage.json.** The brief says the page holds no live jobs; it
  does: branches, tests.yml runs and merges of the public repository, read in the browser since BF1. I kept exactly
  that (the brief's first rule: "it reads only what it reads today"), so a running ring is a public tests.yml run.
  Nothing new is fetched; no session id, no engine. Cost and model names: as before (the Fuel panel, a job's cost in
  its label); the helix adds only the sphere's size and the counter's sum of the same public numbers.
- A job's start in the replay is its first known public event (its earliest tests.yml run in the list, else its last
  push); "merged" is the integration merge that names its code.
- The wheel zooms only when the helix is in focus, in full screen, or with Ctrl (a trackpad pinch); otherwise the page
  scrolls. One finger turns it sideways and still scrolls the page; in full screen it turns freely.
- Changed on purpose, per test: H1 (the model is jobs oldest first, a merge marks its job; it pinned rungs newest first
  and merges as nodes) and H2 (only the canvas is aria-hidden; it pinned the whole box hidden, which now holds the
  slider and the button). The suite pins a tier (`helix.tier('plain')`) so a slow CI machine cannot fall to the SVG mid-check.
- The CHANGELOG keeps its three "inside" lines (the page-fill measure, plan_layout's unreachable checks, the Arabic
  input test): each job's reviewed line, as 0.3.2 kept its "Inside ..." lines. I added and corrected, removed nothing.
- `components`' fade check was not this job's file; it turned this job's run red twice, so I fixed it (R-7) rather than re-run.
- macOS on `release/*`: a two-line change to tests.yml, so this job can do what D-1104-19 asks without pushing a
  second branch.
- `gh` is not in this container; runs were started and read through the GitHub tools.
