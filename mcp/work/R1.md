## Plan (written before any code or run)

### What the code says (read before planning)
1. Buttons: `langButton()` has two branches. With page tabs it copies a tab (the writer's tabs carry `fontColor` and
   switch the container's background, border and shadow off: `frame()` in `pbip-page.js`); that branch was proven on
   the laptop (X1). Without tabs (the case) it writes a button of its own with no `fontColor`, no container setting, and
   `outline.show` true with no colour. Every button DataArcus writes elsewhere (tabs, Reset, Open/Close filters) sets
   `fontColor` and has the container switched off. Microsoft's docs: a button's text colour is a theme default
   (structural colour "secondLevelElements"; Fluent 2 buttons are filled in the first data colour, with their own state
   styles), and the visual container's background is the theme's `"*"` card (white in the case). The pinned schema
   package (`@microsoft/powerbi-core-visual-schema`, actionButton) lists `text.fontColor` and the text margins, without
   defaults. Round 13 (DESKTOP-TESTS.md): a button's icon and text margins "did nothing". So the evidence points at the
   colour (an unset colour on a white panel), not at the height (29 = BUTTON_ONE_LINE, the same rule the proven tabs
   use) nor the padding.
2. Tab order: the mirror (`report-mirror.js`) moves every visual and keeps `tabOrder`, so an Arabic page keeps the
   English reading order; the language button gets `tabOrder` max + 1000 (last). `report-a11y.js` has the writer's own
   reorder (`readingOrder`, `inversions`, exported), used by check_report's A11Y_TAB_ORDER.
3. Title fit: the twin widens buttons and table headers to their Arabic (`fitButtons`, `fitHeaders`); a text box is
   not fitted at all.
4. Text boxes: create_report writes its header title (and logo) with background, border and shadow off (`frame(null,
   ...)`); its "text" slot (`kind: 'text'`) is left to a solid theme on purpose: a panel with a title (round 13). Neither
   writes a subtitle. So the case's title and subtitle are the user's own, left to their theme; the twin copies them.
5. Tables and matrices: the twin changes column widths only (`fitHeaders`), never a text size or word wrap. The writer
   wraps a table's values on purpose (O-14, the owner's go, seen in Desktop: "long issues wrap; Total row readable")
   and sizes its tables by the measured rows (`pbip-sizing.js` TABLE_ROWS). The case's sizes are not DataArcus's.
6. "Days open": a field is one text across the report (`field:<queryRef>`); its draft comes from the fixed glossary
   (`arabic-names.mjs`), which has no draft for it, so the user's assistant drafted it from the measure's name
   ("Avg days open", given to it as `field`). Nothing in the answer says a table row shows one row's value.
7. The matrix: the plan's `cannot` says "a matrix keeps its row headers at the left ... only its values are reversed";
   the approval page shows no `cannot` line at all.

### The fixes, each in the block where its cause lives
1. `arabic-twin.mjs` `langButton()`, the plain branch only (the page-tab branch is unchanged): the text colour set in
   the default selector from the theme's own text colour (the report theme's `foreground`, else `textClasses.label`,
   else Power BI's #252423), checked at 4.5:1 against what is behind it (the page's background colour, the theme's
   page or report background, else white: the button's container is switched off, so the page shows through); the
   outline in the same colour; the container's background, border and shadow switched off as every proven DataArcus
   button has them; no margins written (round 13: they did nothing). Height and width rules unchanged.
2. `arabic-twin.mjs`: each Arabic page's Tab stops in right-to-left reading order (`A11y.readingOrder(..., 'rtl')` per
   group, keeping the page's own numbers, as the writer does), the language button included; on the English pages
   of the copy the language button takes its place in the reading order without moving any other stop's order
   (a free number between its neighbours, else the stops after it shift by one, in order).
3. `arabic-twin.mjs` `fitTextboxes()` (new, beside `fitButtons`): a text box whose Arabic needs more lines than its
   height holds (check_report's TEXTBOX_FITS rule: 10 + 1.8 x pt a line, 0.55 em a character) is first widened toward
   its end (the left on an Arabic page) into free room, then made taller into free room below; what can't fit is said
   (`fitted.textboxesCut`), never pushed over another visual.
4. `arabic-twin.mjs`: on the Arabic pages, a text box WITH text whose own container leaves background, border and
   shadow to a theme that draws a panel (`"*"."*"` or `textbox."*"` background shown) gets the three switched off: it
   is a heading, and every heading text box DataArcus writes has them off (create_report's title). A text box that sets
   one of them itself keeps it (the author chose); an empty text box keeps its panel (that is what it is for). The
   English pages are the original's, unchanged: the plan says their text boxes draw as panels and how to switch it off.
   create_report is unchanged (its title already has them off: a guard check).
5. `report-rules.js`, a new rule TABLE_ROWS_SHOWN (group "sizes", a note; one finding per table or matrix): its text
   size and box, by the writer's measured rows (`pbip-sizing.js` tableHeight, loaded as the one copy), show fewer rows
   than the same box at Power BI's label size for the page (10pt at 720 high, scaled), or its values are set to wrap
   (explicitly): the fix says the size and "Word wrap off" (Format > Values). The twin: a check that no table or matrix
   text size or word wrap changes (it never did). The writer: unchanged (O-14 is the owner's; its tables are fitted).
6. `arabic-twin.mjs` `textsOf()`: a field shown only in tables whose rows are items (a model column among its values)
   says so (`what`: a table column: one row's value), and its draft leaves out the "Avg"/"Average" word (the glossary's
   own draft of the rest, else none); the same field shown elsewhere too keeps its draft and says both.
7. `arabic-twin.mjs` `cannot` (plan and write answers): one plain line for matrices: Power BI's matrix has no
   right-to-left setting, its row headers stay at the left and its columns (months) run left to right, nothing is
   faked; what to do: keep it, or show the same numbers as a table or chart (both mirror). The approval page shows it
   (`approval-window.mjs`, one row in Options; the plan's data carries the line: one line in `server.mjs`).
