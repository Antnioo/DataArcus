## Decisions I made
1. **buildCopy and verifyCopy stay in the facade, not in redesign-patches.mjs:** "copy verification stays independent
   from patch generation"; the patches module makes records only, the copy applies them and its check reads the
   registry and the record list, never the generator (K4). pk1's K5 also reads both bodies in redesign.mjs.
2. **No `reason` field added to a record:** pk1, sp19 and sp38 record the patch list verbatim, and the approved plan's
   canon compares them; a record keeps exactly pointer, from (before) and to (after), and its reason is its kind's
   sentence from the registry, looked up by `kindOfPatch` (K3: every record of the 13 plans has one; a record outside
   every kind has none). kindOfPatch is not called by the plan (that would add words to it); it is the lookup for the
   kinds still to come (RD4, RD6, RD8).
3. **KEEP, twiceOf, reasonOf and schemaOf moved twice:** into redesign-text.mjs in commit 1 (the text needs them; no
   import back from the facade), then into redesign-patches.mjs in commit 2 (they are the policy of what is patched),
   which the text imports. sp38's T1 was narrowed in commit 2 to the text's own exports (its count unchanged); K1 checks
   the policy in its new place.
4. **textPlan made pure:** report.json is read by planRedesign (try/catch, null as before) and handed in; before, it
   was read only when a theme file had to be added: the same value either way (the file is in the strict listing).
   `path.basename(themeRel)` became `themeRel.split('/').pop()` (the report's relative paths use "/").
5. **sp38 records the whole answer verbatim** (not only its sha256): a failure shows the first difference.
6. The lab cases (S12, S13) use the CS1 lab (no randomness: its .platform id is fixed); 3 runs identical.

## Seen, not in scope
- verifyCopy accepts a copy where a planned patch was not applied when the file stays byte-identical (it checks the
  files that changed, not that every patch's file changed). buildCopy always applies them, so no copy today misses one;
  a check that every patched file differs (or holds the record's value) would close it. Found while writing V3.
- Root `npm run lint` needs the root packages (`npm ci` at the repo root): a fresh container without them fails with
  "Cannot find package 'globals'".
