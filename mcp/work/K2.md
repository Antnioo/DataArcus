## Plan (written before the code)
**What is wrong.** create_report's plan keeps the exact files (`tools/plan_layout.mjs: exactArtifact`), the approval
records their digest (`lib/plans.mjs: approve`, `art.binding`) and the write writes those bytes
(`tools/create_report.mjs: writeApproved`). The twin's write instead calls `planTwin` again and serialises that
rebuild; `.platform` gets `crypto.randomUUID()` at write time; no digest is compared. Today the pinned labels, terms,
options and the two prints keep it equal, but any future non-determinism in `planTwin` would write files nobody saw.

**The fix.**
1. `lib/twin-write.mjs: twinTree(P)`: the whole tree the write writes, built from a plan's `P` (the twin or the copy,
   the original's unchanged files read now, the month script when offered and free, the .pbip), with its digest
   (`lib/artifact.mjs: digestOf`, create_report's helper). `twinOutputs` reads the same tree's paths.
2. The `.platform` logical id is chosen once, in `planTwin` (`a.logicalId`, else a new one), and used by the twin's
   tree and by `languageCopy`: the approved bytes include it.
3. The plan (`tools/create_arabic_twin.mjs`): `Plans.attach(id, art)` with the tree, its digest and
   `bindingOf(digest, pin, modelPrint)` (pin: the plan's labels, terms, options and source print), so `approve`
   records the binding as for create_report. The approval page's pictures (`twinPreview`) are drawn from the tree.
4. The write: the gate and every check of today (options, labels, terms, source print, model print, names free), then
   the kept tree's digest and binding against the approval, then a rebuild (`planTwin` with the plan's inputs and its
   logical id) whose tree's digest must equal the approved one; then `writeTree` of the KEPT tree. Any difference:
   "Nothing was written: ...". No kept files (a restart, the 64 newest kept): refused, make the plan again.
5. The bilingual report (X2): checked, already inside create_report's exact artifact (see Results for the line).
6. "Not fully Arabic": one short line (EN and AR) in the twin's plan, its write answer and the approval page, built from
   what `cannot` already found for this report; left out when nothing applies.
7. ARCHITECTURE.md's "One write" says create_report and the twin.

**Tests first (red on c3d7fd4).** New `mcp/test-0.3.1-twin-artifact.mjs` (in-process, the tool's own handler, the

not see (the month script's file in the project folder, removed or added between the go and the write) is refused

"Not fully Arabic" line names what this report has and is absent for a report with none of it. Mutation: `K-twin-digest`
(the digest comparison skipped) must be killed by the new suite.
