## What changes from #85 (decided before the work; why)
- **No stage, no source tree in the plugin.** #85 copied `mcp/`'s code and the engines into the plugin (`stage.mjs`).
  The brief: the folder is copied as-is into a new public repo, and the server points at the released `.mcpb`. Claude
  Code's plugin reference (read 25 Oct) accepts an `.mcpb` bundle URL in `mcpServers` ("Downloads the bundle into
  `.mcpb-cache/`, then reads it"); the release `v0.3.0` on `Antnioo/dataarcus-releases` carries
  `dataarcus-0.3.0.mcpb` (SHA-256 aa23ace8..., matches its notes). So the plugin carries no DataArcus code at all: the
  public repo holds manifests, skills, a README and an MIT licence for those files.
- **Copilot CLI cannot read an `.mcpb`** (its plugin reference names stdio `command`/`args` servers only), and DataArcus
  has no published npm package (`dataarcus-mcp` is `private`, not on npm). So the Copilot plugin carries the skills
  only, and the README adds the server by hand with `copilot mcp add` (`node <unzipped .mcpb>/mcp/server.mjs`).
- **The version:** one place in the folder, `plugins/dataarcus/.claude-plugin/plugin.json` `version`; the bundle URL in
  the same file and the three other manifests must say the same (the test). 0.3.1: the routing skill describes 0.3.1's
  options (the Arabic lens, `languages: "en+ar"`), which the 0.3.0 bundle lacks. The owner copies the folder after
  `dataarcus-0.3.1.mcpb` is on the releases page ("For the owner").
- **report-design** (the full steps) ships as a copy in the folder, kept byte-identical to `mcp/skills/report-design/
  SKILL.md` by the test (the one source stays `mcp/skills/`).

## Decisions I made
- **The server is the release `.mcpb` from its URL** (Claude Code's documented bundle URL in `mcpServers`), not a
  copy of the code (#85's stage) and not npx (no npm package exists; publishing one is the owner's call). The plugin
  then carries no DataArcus code, and users get the same file the release notes hash.
- **Copilot CLI: skills in the plugin, the server by hand** (`copilot mcp add` on the unpacked bundle): Copilot can't
  start a bundle. Rejected: a launcher script in the plugin that downloads and unpacks the bundle (code to maintain,
  a network call at every start, a hash check of our own).
- **Version 0.3.1 in the folder**, not 0.3.0: the routing skill names 0.3.1's options (the Arabic lens, `languages`),
  which the 0.3.0 server refuses. The one place is `plugins/dataarcus/.claude-plugin/plugin.json`; the bundle URL,
  three manifests and the README's file names must match it (the test), and it must be the newest release in
  mcp/CHANGELOG.md or the next one.
- **The hard dependency on `powerbi-authoring@fabric-collection` stays** (Claude Code only), as in #85: one install
  gives both. Its cost: three commands, Microsoft's marketplace first (measured).
- **Licence field "MIT"** in both plugin manifests: it describes the plugin's files; the README says the server is
  under DataArcus's licence. #85's `LicenseRef-DataArcus` would have said the MIT folder is not MIT.
- **No `repository` field** in the manifests: the public repo's name is the owner's; the README names
  `Antnioo/dataarcus-skills` as the brief's example.
- **`report-design` as a byte-identical copy**, checked by the test, so the plugin works from the folder alone and
  `mcp/skills/` stays the one source.
- **No icon, no image** in the folder (no Microsoft logo by construction; ours would need the owner's pick).
- **C's sample project not in the routing skill:** its branch had not landed (`feat/0.3.1-sample-project` holds only
  C.md); when it merges, one row ("show me what DataArcus can do": `plan_layout` with `sample: true`) and the test's
  option list get one entry each.
- **The claims rule is the new test's own** (it bans "free" and "Skills for Fabric" listing wording that
  `0.3.0-claims` bans differently); the folder is not added to `0.3.0-claims`' SPEAK list, which forbids naming
  Microsoft's Power BI Report skill, the folder's subject.
