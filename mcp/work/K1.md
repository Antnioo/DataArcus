## Decisions I made
- The prototype lives in `mcp/skills-packaging/`, not a top-level `skills/`: `mcp/` is excluded from the website build
  (a top-level folder would be published on dataarcus.com) and moves with `mcp/` to the private repo.
- Plugin id and marketplace `dataarcus`, display name "DataArcus for Power BI" (the .mcpb's name); the routing skill
  `dataarcus` beside the existing `report-design` (copied in by the stage, not duplicated).
- A hard dependency on `powerbi-authoring@fabric-collection` in the Claude Code marketplace entry only (not in
  plugin.json, which Copilot reads too). Unversioned: Microsoft tags no plugin releases.
- The server ships as source in the plugin (`server/`), started with `node`, npm packages installed by Claude Code from
  the plugin root; not as the .mcpb (Copilot can't read a .mcpb; Claude Code skips a .mcpb for project-scope plugins).
- The working folder: Claude Code `userConfig` (`type: directory`, required); Copilot gets `${DATAARCUS_ROOT}` from the
  environment (unexpanded, the server's own rule makes it "no folder", so nothing is read or written).
- Licence field `LicenseRef-DataArcus` with the repo's LICENSE copied in.
- The version comes from `mcp/package.json` (0.1.0 today), stamped by the stage; the source manifests carry none.

## Seen, not in scope
- `mcp/package.json` says 0.1.0 while the .mcpb releases say 0.2.x (audit A8-8, open): a published plugin would show
  0.1.0 until that is settled.
- Copilot CLI: whether `${DATAARCUS_ROOT}` in a plugin server's `env` is expanded is not documented; if not, Copilot
  users can't set the folder without editing their MCP config (laptop check below).
- Microsoft's plugin starts `npx -y @microsoft/powerbi-modeling-mcp@latest` (unpinned) at every session; a hard
  dependency means DataArcus users get that too. The owner may prefer a recommendation over a dependency.
- The stage duplicates part of the private build's job (audit A8-7: build.mjs should write dist/plugin); when the owner
  publishes, the release build should own it.
- Cursor / Windsurf / Codex / VS Code: no APM manifest yet.
