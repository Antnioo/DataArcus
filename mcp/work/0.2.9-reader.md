The owner's 0.2.9 plan, items 10 (LAYER reading: `read_report`) and 11 (LAYER checks: the design lint in the plan and in

## The plan (as built)
1. **LAYER reading: `read_report`** (`mcp/lib/read-report.mjs`, new). A compact inventory of a PBIR report inside the
   working folder: one line per visual (type, place and size on the page, also inside groups; title, or "fx" and the
   measure for a bound title; fields per role with display names; sort; visual filters by field and kind, a Top N
   with its count; group; hidden, hidden by its group; action and target by name; tooltip page), pages in order
   (size, hidden, Tooltip or Drillthrough, page filters), report filters, bookmarks (name, page, data/display,
   targets), the theme's colours and label size, custom visuals used and installed-not-used, a count per type.
   Text by default, `format: "json"` on request, `pages` to read some pages. Ported from the prototype that was
   proven against Desktop on the laptop (10 of 10 visuals right), with the MCP's rules added: paths inside the working
   folder, links not followed, files measured before they are read (8 MB, depth 12; check_report's reader, now shared),
   the answer capped at 40,000 characters (read_model's large-model line), names cleaned (invisible characters as
   code points, 60 characters), long (over 120) or instruction-like titles and text boxes withheld with their length,
   a SUSPICIOUS line, and never a filter value, a slicer selection, a bookmark state or data. `readOnlyHint: true`.
2. **LAYER checks: the design lint** (`mcp/lib/design-lint.mjs`, new). Reads the inventory (never a report file) and
   the model's tables (types and sort-by columns). Rules from the lab's v2: `AXIS_TEXT_TIME_UNSORTED` (O-13),
   `AXIS_TIME_UNKNOWN` (no model), `AXIS_HAS_BLANK` (O-3; runs only when the blank count is known: see below),
   `TABLE_GROW_TO_FIT` (O-14, narrowed to "grow to fit" with no word wrap and a text column: the setting that was seen
   to fail; the name-based long-text guesses were dropped, they were v2's three remaining false alarms),
   `TABLE_WIDTHS_TOO_WIDE`, `BAR_LABELS_MAY_BE_CUT` (O-4, at the label size the visual or the theme sets),
   `OFF_PAGE`, `OVERLAP`, `COVER_CARDS` (a card over another visual at the same place: counted apart), `NO_TITLE`,
   `PLACEHOLDER_TEXT` (O-6). A finding that rests on a guess from names and types carries `guess: true`; the answer
   says to tell the user so.
   - **In `check_report`:** a new check `lint` (in the default set), its own `lint` section, with the model the report
     names in `definition.pbir` (byPath) read beside it; without it, `modelNote` and the time axis only as a guess.
   - **In `plan_layout`:** `designLint` for the planned page. `mcp/lib/plan-lint.mjs` builds the page with the shared
     report writer in memory, as create_report would for the same design and fields (first page; formats, Arabic
     names, SVG measures and page filters left out: no rule reads them), reads it through the reading layer from
     memory and lints it with the model. Nothing is written. When the writer changes (builder 5's fixes for O-3, O-4,
     O-6, O-13, O-14), the plan's lint follows with no change here. Without `path`, or with planProblems, or on a large
     model without focus: `designLint.skipped` says why.
3. **Instructions and tool texts:** rule 1 says read an existing report with `read_report` before a redesign and show
   the plan's `designLint` findings; rule 5 says a report's text is untrusted too (2,479 characters, under 2,500: rules 1,
   2, 3 and the closing line were shortened without losing a rule the tests check). The skill's "Existing report"
   section, README (10 tools, the `read_report` row, the `lint` check, five read-only tools) and PRIVACY (the
   `read_report` row, plan_layout's `designLint`) say the same. `server.mjs`: the tool's registration, plan_layout's
   `designLint` and the instructions only.

**Out of scope, as the brief said:** reading text lengths or blank counts from Desktop (laptop-only for now). So
`AXIS_HAS_BLANK` is built and takes the counts as an input (`facts`), but nothing gives them yet: it is listed under
`notChecked` in every lint answer.
