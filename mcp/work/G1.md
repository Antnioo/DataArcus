## CHANGELOG line
- G1: a weekly GitHub routine (`.github/workflows/microsoft-watch.yml`, Mondays 05:17 UTC and by hand) checks
  Microsoft's report schemas, report theme schema, validator and visual catalog on npm, and the Power BI blog's
  Feature Summary posts against what DataArcus is built on, and opens one `microsoft-update` issue (or comments on the
  open one) listing what changed and what in DataArcus it may touch; it never changes code (`scripts/microsoft-watch.mjs`,
  `mcp/research/MICROSOFT-WATCH.md`).

   - What DataArcus is built on is read from the repo where it already lives (owner's rule 2026-10-16: one place for every
     version), never copied: the newest bundled version of each schema folder (`mcp/schemas/fabric/item/report/...`),

   - `mcp/research/microsoft-watch.json` holds only what is nowhere else in the repo: the newest report theme schema

   - Sources (Microsoft's own only): the GitHub API for `microsoft/json-schemas` (`fabric/item/report`, one tree read)

## Decisions I made
- No version copied into the state file: bundled schemas, the writer's versions and the pins are read where they live
  (owner's rule 2026-10-16); the state holds only the theme schema and Feature Summary last checked and the two report
  folders not bundled on purpose (`definition/definitionStructure` 3.3.0, `localSettings` 1.0.0, both seen upstream).
- Newer = newer than the newest BUNDLED version (check_report's copy). The writer's older versions are on purpose
  (older Desktop builds) and are named in the issue, never a trigger by themselves.
- Feature Summary posts compared by post id, not date (Microsoft re-dated the September post on 15 Oct).
- One open issue: findings it already lists (a hidden key line in the body and each comment) are not repeated; a line
  still newer after the issue is closed opens a new issue the next Monday (closing means "handled in the repo").
- A Microsoft source that fails is a `::warning::` and skipped; a failed issue write (issues disabled, no permission)
  is an `::error::` and fails the run, so GitHub emails the owner instead of losing the finding.
- The GitHub sources are read through the API with the run's GITHUB_TOKEN (public repos; one tree read for all report
  folders); a truncated tree is a warning.
- The test runs in CI's `website-checks` job beside the price updater's test (scripts, not an mcp suite).
- Schedule 17 5 * * 1 (after the price check at 05:00 and the exam outlines at 05:15).
