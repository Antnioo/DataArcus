# G1: a weekly watch on Microsoft's Power BI updates (issues only)

Branch `feat/0.3.0-microsoft-watch` from `origin/integration/0.3.0-wave` (7c2149c). Pushed only; no PR, no merge.
The owner, 19-20 Oct: "make it routine on github on rep to check Microsoft updates regarding themes and stuff".

## CHANGELOG line
- G1: a weekly GitHub routine (`.github/workflows/microsoft-watch.yml`, Mondays 05:17 UTC and by hand) checks
  Microsoft's report schemas, report theme schema, validator and visual catalog on npm, and the Power BI blog's
  Feature Summary posts against what DataArcus is built on, and opens one `microsoft-update` issue (or comments on the
  open one) listing what changed and what in DataArcus it may touch; it never changes code (`scripts/microsoft-watch.mjs`,
  `mcp/research/MICROSOFT-WATCH.md`).

## Plan
1. This file, pushed first.
2. Tests first: `scripts/test-microsoft-watch.mjs` (fixtures, no network), run in CI's `website-checks` job beside the
   price updater's test (`.github/workflows/tests.yml`).
3. `scripts/microsoft-watch.mjs` (Node 22, built-in `fetch` only, no new dependency):
   - What DataArcus is built on is read from the repo where it already lives (owner's rule 2026-10-16: one place for every
     version), never copied: the newest bundled version of each schema folder (`mcp/schemas/fabric/item/report/...`),
     the writer's versions (`assets/js/pbip-query.js` SCHEMA, `reportExtension` in `assets/js/pbip-export.js`), the two
     pins (`mcp/package.json`).
   - `mcp/research/microsoft-watch.json` holds only what is nowhere else in the repo: the newest report theme schema
     DataArcus was checked against (2.159, U1), the last Feature Summary read (October 2026, id 5374650, U1), and the
     report folders Microsoft publishes that DataArcus does not bundle on purpose (`definition/definitionStructure` 3.3.0,
     `localSettings` 1.0.0), with the version seen.
   - Sources (Microsoft's own only): the GitHub API for `microsoft/json-schemas` (`fabric/item/report`, one tree read)
     and `microsoft/powerbi-desktop-samples` (`Report Theme JSON Schema`), with the run's GITHUB_TOKEN (read of public
     repos); `registry.npmjs.org` (dist-tag latest); the Power BI blog's RSS (`powerbi.microsoft.com/en-us/blog/feed/`).
   - Changes: a bundled folder with a newer version; a folder neither bundled nor listed (new); a listed unbundled
     folder with a newer version; a newer theme schema file; a newer npm `latest`; a "Feature Summary" post with a
     higher post id than the last read (ids, not dates: Microsoft re-dated the September post on 15 Oct).
   - One issue, label `microsoft-update`: none open -> open one; one open -> comment with only the changes it does not
     already list (a hidden key line in the body and each comment); nothing new -> nothing written. Never code, PRs or
     merges. A Microsoft source that fails (network, HTTP error, unreadable answer) is a `::warning::`, that source is
     skipped, the run passes; a failure to write the issue is an error (the change would be lost silently).
   - `--dry-run` prints the issue (or the comment) and writes nothing.
4. `.github/workflows/microsoft-watch.yml`: cron `17 5 * * 1` + workflow_dispatch; permissions contents read, issues
   write; checkout + setup-node (the pinned SHAs the other workflows use); `node scripts/microsoft-watch.mjs`.
5. `mcp/research/MICROSOFT-WATCH.md`: what it checks, how to run it by hand, what to do when an issue opens.
6. Suites: the new test; `node scripts/test-site-config.mjs` (a repo-wide check; no page changes); `node
   scripts/test-deny-scan.mjs`. No mcp/ code changes, so no mcp npm test run needed beyond confirming no file it reads
   changed. A live dry run from here (GitHub API is blocked in this sandbox: those two sources are expected to warn).
