## Decisions I made
- **No language input.** The brief named "the page language in"; every download is English on both pages today (the
  AR records are byte-identical to EN), so a language input would be unused. RD3's Arabic handbook adds it when there
  is something to choose; the interface takes one object, so adding a field breaks no caller.
- **The date is an input** (the page passes today's UTC date): the module reads no clock, so the same input always
  gives the same file (M2), and the suite writes the date as `<DATE>`.
- **What stays in model-health.js:** `download()` (a Blob and a link: DOM), the score card (a canvas picture, not text;
  covered by model-health's I-1 checks), `copy()` and the Fix plan's scripts (copied, not downloaded). The view's
  `srcOf` stays (the Issues tab's source line); `srcEn` and `qWhere` moved (only the downloads used them).
- `esc` is copied into the module as a private one-liner (as SP9 and SP15 did for their helpers); the findings' area
  names are the module's `AREA` (English only; the page's CAT keeps its Arabic names and icons).
- The findings CSV keeps writing every cell with `String(x)` and the measures CSV with `x == null ? '' : x`, exactly as
  before (one `csv()` helper, the findings' cells turned to text first).
- sp24 builds its .pbit and .zip files with the site's own ZIP writer (`pbip-zip.js`, as sp5 does), so no second ZIP
  writer is added; the models come from `mcp/fixtures/health-models.mjs` (one place) plus one new made-up model with
  no measures. The incomplete model shows no result, so it records no downloads (recorded as none, checked as none).
- Stamps: `20261103sp24` for health-downloads.min.js (new) and model-health.min.js, both tool pages; the worker and
  the engine are unchanged.

## Lessons for the reviewer
- health-worker-client.js: the worker sets `result.meta` (fileName, source, hasReport, analyzedAt); the downloads read
  `meta.fileName`, so the client must hand the view the result with `meta` set. The engine's analyze() alone has none.
- health-view.js: the view calls `window.MHDownloads.build(kind, { result, rules, score, date })` through one helper,
  `save(kind)`, and keeps `download()`; `score()` (ignored rules out) is the view's, passed in.
- sp24's records are the downloads' contract: a view split must leave D1-D20 unchanged.
