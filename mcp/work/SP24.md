# SP24 (0.3.2, the split): assets/js/model-health.js -> health-downloads.js (the Model Health Check's downloads; behaviour identical, site only)

## Summary
- **Approval:** the reviewer's brief "SP24" (3 Nov); the owner D-1016-01, D-1102-02, D-1103-10, D-1103-11. Backlog
  B-280, B-286 (the Codex split map ## 11: health-downloads.js first, then health-worker-client.js and health-view.js).
- **Base:** `feat/0.3.2-sp24` from `origin/integration/0.3.2` at 83666ef. Push only this branch; never merge.
- **Scope:** new `assets/js/health-downloads.js` (`window.MHDownloads`, `module.exports` in Node) holds the four text
  downloads of the page: the findings CSV (Issues tab), the HTML and Markdown documentation and the measures CSV (Docs
  tab), with the helpers only they use. model-health.js calls it and keeps the file selection, the worker, the loading
  UI, the views, `download()` (the Blob and the link: DOM) and the score card (a canvas picture, not text).
- **The interface (D-1103-11):** one input, one output, no state.
  `MHDownloads.build(kind, { result, rules, score, date })` -> `{ name, type, text }`.
  `kind`: `findings-csv`, `measures-csv`, `doc-html`, `doc-md`. `result`: the worker's analysis (metadata only);
  `rules`: the engine's RULES; `score`: `{ overall, perf, maint, bp }` as the page shows it (ignored rules out);
  `date`: `YYYY-MM-DD` (the page passes today; the module never reads a clock). No DOM, no window reads, no storage,
  no worker; it never changes its input. Also `MHDownloads.confirmWhere(question)` (the evidence line of a "please
  confirm" question, shared with the Issues view: one place).
- **Loaded** before model-health.min.js on both tool pages; checked in test-site-config.mjs (both pages, once, before).
- **Website suite sp24 (scripts/tests/sp24.mjs, shard 1), recorded on the base:** 10 made-up models through the
  page (the sample; the tricky DAX as a model.bim (a measure with a quoted string); the Arabic model with a legacy
  report as a .pbit (Arabic table names); the DAX tables and a function; a model with no measures; legacy.pbit;
  Health Test.pbit; the Ramadan TMDL project zipped; the health PBIP project zipped; the incomplete TMDL project). EN
  and AR pages: every download button clicked, each file's name and exact text recorded (fixtures/sp24-downloads.json,
  the date written as a fixed mark). D1-D20: one per model per language. After the move: M1 the four builders live in
  health-downloads.js and not in model-health.js; M2 in Node, build() of each kind on two models analysed by the engine
  is the same on a second call and leaves its input unchanged, and the module's source reads no DOM, clock, storage
  or worker; M3 both pages ask for health-downloads.min.js before model-health.min.js.
- **Expected checks:** sp24 20 on the base, 23 after. Unchanged: model-health, sp9 3, sp15 3, tmdl-model 70, pbip 111;
