## The interfaces
- **window.SiteNavigation.init()** (DOMContentLoaded). In: the DOM, window.AOS, window.bootstrap, reduced motion,
  the viewport width. Out: DOM changes only, and one event per live report opened: document `dataarcus:embed`,
  detail `{ dashboard }` (the title without " - DataArcus"). **whatsapp()** (script time). In: commonTranslations
  `wa`, `<html lang>`. Out: the floating button in an `<aside>`. No tracker, no consent.
- **window.SiteForms.init()** (DOMContentLoaded): `attach()` for #contact-form and #beta-form, and the validation UX.
  **attach(form, result)**: In: the form, its result box, commonTranslations `formMsg`. Out: a JSON POST to
  Web3Forms, DOM changes, and after a 200 one event: document `dataarcus:lead`, detail `{ formId }`. No tracker.
- **window.SiteAnalytics.init()** (script time): sets `window.dataArcusTrack(name, params)` (gtag event with
  page_type, Clarity event, each only when present) and every listener (clicks, form_start, dashboards, article read,
  language, blog search via safeTerm, filters, AI referral); it reads only `formId` from `dataarcus:lead` and only
  `dashboard` from `dataarcus:embed`. **banner()** (script time, after init): the cookie banner on
  `window.daConsent`. The only site file that names gtag, clarity, daConsent or dataLayer (sp35 M2).
- **main.js**: `SiteAnalytics.init()`, `SiteNavigation.whatsapp()`, `SiteAnalytics.banner()` at script time (the
  order sections 7, 8, 9 ran in), then on DOMContentLoaded `SiteNavigation.init()`, `SiteForms.init()`.

## Decisions I made
- The cookie banner (section 9) goes with the analytics adapter: consent is enforced in one file.
- The live report facade (inside section 7 before) moves to navigation; it tells analytics by `dataarcus:embed`, as
  the form tells it by `dataarcus:lead`; the adapter reads only the named field of each.
- The WhatsApp button (8) moves to navigation (a widget); the adapter's click listener still counts it.
- On DOMContentLoaded section 6 (Escape, blog filters) now runs inside `SiteNavigation.init()`, before the forms
  (it ran after them): they listen on different targets or events; sp35 records both orders the same.
- The facade's listener is now added on DOMContentLoaded (it was at script time): nothing can click between the two.
- No `track` in SiteAnalytics' return: the tools already use `window.dataArcusTrack`, one entry point.
- main.js calls `window.SiteX` (no new ESLint globals); the AOS and bootstrap globals now name site-navigation.js.
- 15 sessions, not the plan's 13: the article read (Playwright's clock) and reduced motion with AOS blocked.
