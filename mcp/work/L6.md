## CHANGELOG line
- L6 (0.3.1): `daxFunctions` (off by default): create_report writes the DataArcus DAX function library (DA.Sparkline,
  DA.BulletBar, DA.KpiCard, DA.StoryTitle, DAX user-defined functions) and the measures that call them into ONE TMDL
  script next to the project ("<report> - DAX functions.tmdl"), which the user applies in TMDL view: its first step,
  said first in the plan, on the approval page and in the script's own header, is that applying it raises the model's
  compatibility level to 1702, which cannot be undone (said "already 1702 or higher" when the model's files say so).
  The report then shows a sparkline column (last 12 months, only with a related date table), a bullet bar where the
  model names a target, the KPI cards as HTML pictures in the theme's colours, and story titles on the charts; text
  escaped inside the functions, numbers in en-US, no value read. Pinned by the plan; check_report gives a note until
  the script is applied. (L6)

## What the lab proved (the brief; owner's laptop, 10 Oct 2026, Desktop 2.158.1304.0, a copy at compatibility 1702)
- The four functions loaded and drew on the first open; the signatures and parameter types (STRING, NUMERIC, BOOLEAN,
  INT64, ...) accepted; Save As writes `definition/functions.tmdl` (lineage tags, `///` descriptions), database.tmdl
  keeps 1702, model.tmdl has no reference. A dotted name is quoted in TMDL, not in DAX.
- Points as a text list split with SUBSTITUTE + PATHITEM; SVG numbers with FORMAT(x, "0.0", "en-US"); % as %25 and #
  as %23; rgb() colours; Image URL data category for picture measures; titles bind to visualContainerObjects.title.text.
- Open points fixed here: compatibility said first; a blank item (VALUE("")) guarded inside; sparkline width/height
  parameters; the period of the delta a parameter; the Arabic title isolates the leader (U+2068/U+2069); KpiCard
  colours from the theme (good/bad/text/card); the Arabic card dir="rtl".
- Microsoft Learn (read 20 Oct, "DAX user-defined functions"): UDFs need compatibility 1702 and are "generally
  available in Power BI Desktop and Power BI Service as of the June 2026 release"; TMDL view shows a compatibility
  upgrade prompt when an applied object needs a higher level; function names may hold dots, parameter names only
  letters, digits and "_"; UDFs cannot go in display folders. (Recorded, not decided: the release call stays the owner's.)

## Decisions I made
- **Option**: `daxFunctions: true | ["sparkline", "bulletBar", "kpiCards", "storyTitles"]` (true: all four where they
  fit); left out or `false`: off, no script, the files as without it. In `REPORT_LOOK` (pinned, filled from the plan;
  another value at create_report refused, nothing written) and `LOOK_DEFAULTS` (`false`). The library is written whole
  whichever uses are asked (it is the library; the uses are where the report calls it).
- **One script, one helper**: `mcp/lib/dax-functions.mjs` builds it; `mcp/lib/model-script.mjs` gained
  `functionLines` (a model-level function as Desktop saved the lab's functions.tmdl: `///` lines, the dotted name
  quoted, the body one level deeper than the parameters, not fenced, then its lineage tag), `compatOf` (the level from
  model.bim or database.tmdl, as the model reader gives it) and `COMPAT_UDF` 1702. Measures through `Fix.measure`
  (fenced, as L3-L5), under `ref table`, folder "DataArcus DAX functions", Image URL for the pictures. Tags from the
  plan's seed (the same plan gives the same bytes). `assets/js/tmdl-model.js` already reads `function` objects (the
  suite reads the script back and as a project's functions.tmdl): not changed.
- **The script's own header**: TMDL has no comment syntax in Microsoft's docs, so the header is the first `///` lines of
  the first function (DA.Sparkline): the library's name, then "FIRST: applying this script raises your model's
  compatibility level to 1702 ... It cannot be undone." It becomes part of DA.Sparkline's description in the model
  (a laptop check: whether a `//` line is accepted instead).
- **Compatibility first**: the plan's answer opens with `daxFunctions` and its `sayFirst` (read from the model: "from
  1567 to 1702", or "already at 1702"); the approval page's first heading is "First: this raises your model's
  compatibility level (cannot be undone)" above the preview; create_report's answer opens with it and `howToApply`;
  the app's prompt summary too. The "writes" list is not changed (it lists files).
- **A function the model already has**: the library's own text (whitespace aside): left out of the script, said
  (`alreadyInModel`); its own function under a DA.* name: a plan problem (a script never replaces anything).
- **The functions** (the lab's, with the open points fixed): DA.Sparkline(points, colour, width, height): blank items
  left out by a FILTER before VALUE, no points or only blanks give BLANK, a flat series divides by 1, the end dot on the
  last non-blank point; DA.BulletBar(actual, target, maxValue, goodWhenUp, good, bad, track, mark): a blank or zero max
  counts as 1, a blank actual is blank, a blank target draws no mark (the lab's red-when-over became goodWhenUp, so a
  sales target and a cost target both read right); DA.KpiCard(title, valueText, delta, goodWhenUp, width, height, four
  colours, lang): title and value escaped inside (% then # then & < >), dir rtl in Arabic with the pill kept ltr, no
  pill for a blank delta, fonts from the card's height (not measured: laptop); DA.StoryTitle(leader, valueText, noun,
  delta, period, lang): the period a parameter, in Arabic the leader, value, noun and percent each isolated (U+2068 /
  U+2069), a blank leader gives a blank title. Parameter names letters only (Microsoft: no dots; `text` avoided).
  A colour parameter loses quotes and tags, and # becomes %23.
- **Numbers**: the pictures' numbers FORMAT(x, "0.0", "en-US"); the points the sparkline measures pass are whole
  numbers (ROUND(x * 10000) in "0", en-US), so VALUE never parses a decimal separator whatever the culture.
- **The uses**: sparkline: the first measure of each report-page table, the last 12 months with data in the selection,
  by a table marked as a date table with a date key related directly to the measure's table (the flip cards'
  `calendarFor`, now exported); none: not used, told. Bullet bar: each table measure whose target the model's metadata
  names (the status icons' `targetOf`, now shared), max = MAX(actual, target) x 1.25 per row, at or above the target
  good. KPI cards: every card of the KPI row becomes an Image visual of its DA.KpiCard measure (box, name, tab stop,
  group, alt text kept; the year on year by the date table, else no pill); not with `flipCards` (both turn the cards:
  a plan problem; flipCards with the other uses is fine). Story titles: each bar or column chart of one measure by one
  category, its `visualContainerObjects.title.text` bound to the measure; the static title stays its alt text.
- **The table's picture columns** (layout, so tested first against my first build, which appended them unsized: 4
  checks red): the writer's svgColumns rule (pbip-page.js, measured 4-5 Oct): every other column keeps its room
  (columnRoom plus the cell's padding, 24 at 1080) and shrinks only into its slack, the pictures share what is left
  (imageWidth at most 120, height by 120 x 30, each column + 10), never past the box; under 48: no picture column, told.
  Right to left: the pictures at the reading end (the left), after hidden helper columns.
- **check_report**: `DAX_MEASURE_PENDING` (a note, never "can break") for a visual showing a measure named by the
  library's suffixes that the model does not have yet; the flip cards' IMAGE_MEASURE_PENDING is not given for those.
  The plan's exact build counts the script's measures as the model's (pending), as L4/L5.
- **Not changed**: the shared engines in assets/js (no website change: no build:min, no ?v=, no sitemap).
- **Microsoft Learn** (20 Oct) calls DAX UDFs generally available since June 2026; recorded only: whether this ships
  in 0.3.1 stays the owner's call.
