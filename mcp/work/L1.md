## What the code has (read before planning)
- check_report (`mcp/lib/check-report.mjs`) already tells each page's language (S1 `pageLanguages`: language buttons,
  the pages that reach a page, its own texts, else the report's), who built the report (`builtByOf`) and the approved
  route for a DataArcus report (`fixRoutesOf`). Its rules come from `assets/js/report-rules.js` (RTL_MIRROR: a title
  aligned left, a page navigator) and `assets/js/report-a11y.js` (A11Y_TAB_ORDER, `byDir`).

  Arabic text with a Latin run not isolated); report-rules.js has no bidi rule.
- What the twin does per visual kind is `report-mirror.js` (`kindOf`, `KIND_WHAT`, `mirrorVisual`); what it cannot is
  in `arabic-twin.mjs` (`MATRIX_SAID`, the `cannot` lines: slicer items, the page navigator, data values). The Arabic
  calendar columns are `arabic-calendar.js` (`kindOf`, `arabicOf`: "<name> (Arabic)") and add_gulf_calendar's
  `arabicColumnsOnly`.
- A mirrored visual has marks the lens can read without running anything: a bar chart's `categoryAxis.switchAxisPosition`
  and `valueAxis.invertAxis`; a column/line/combo chart's `valueAxis.switchAxisPosition`, its category sorted Descending;
  a table's first column a measure (reversed); a pill slicer sorted Descending; text boxes and titles aligned right.

## Plan (each part in the block where its cause lives)
1. **`mcp/lib/arabic-lens.mjs` (new): the lens.** It reads the report once (the reading layer's `inventory`, check-report's
   `rulesInput`), takes each page's language from S1's `pageLanguages` and who built it from `builtByOf`/`fixRoutesOf`
   (exported from check-report.mjs, unchanged), runs the existing rules as a right-to-left reader would (RTL_MIRROR and
   A11Y_TAB_ORDER through `Rules.check` with every page right to left) and words them per page; its own selections:
   - reading direction: the page's heading (its top text box, else the top-left visual) on the left half or aligned
     left; tab order (A11Y_TAB_ORDER, right to left);
   - texts: an Arabic text with a Latin run not isolated (`isolateLatin(t) !== t`, the one copy); an Arabic text box
     aligned left; English-only titles, text boxes, buttons and page names on a page meant for Arabic; on an English page
     the count of texts the twin's labels translate;
   - charts: bar charts not mirrored; column/line/combo/area charts not mirrored, the time ones named (time told by the
     mirror itself: `mirrorVisual` with timeRightToLeft true and false give different sorts) with `timeRightToLeft`;
     waterfalls (Power BI has no right-to-left waterfall: `waterfallRtl` "mirror" is DataArcus's stacked-column one);
     tables in left-to-right column order (the twin reverses them: yes); matrices (`MATRIX_SAID`: only the measures'
     order today);
   - calendar values: a visual showing a date table's month, day, quarter or Hijri name column with no "(Arabic)" twin
     in it: `add_gulf_calendar` `arabicColumnsOnly` names the columns ("Month Name (Arabic)", "<name> (Arabic)");
   - slicers: dropdown and list items keep Power BI's alignment and text direction (no setting: said); pill slicers
     (one row of buttons) in left-to-right order (the twin sorts them descending) and values not centred (P7's rule);
   - page navigation: the page navigator (no order setting, RTL_MIRROR's own words); a row of page buttons in page order
     from the left; English button texts (texts rule).
   Each finding: `{ id, rule, page, visual?, count?, what, fix }`, fix `{ kind, how, tool?, options? }`, kind one of
   `twin` (create_arabic_twin and its options: an English page, or a DataArcus copy/twin's Arabic page), `model`
   (add_gulf_calendar `arabicColumnsOnly`: a model step), `desktop` (a Power BI setting the person changes by hand, named:
   an Arabic page of a report DataArcus did not write), `none` ("Power BI has no setting for this: say so", with
   DataArcus's alternative when one exists). Per page and rule one finding (counts inside), so the list stays short.
   The answer: `summary` first (N findings over M pages, the 3 that matter most, the one call that fixes most, "no Arabic
   pages yet: create_arabic_twin" when no page is Arabic; at most 1,200 characters), then `pages`, then `findings`,
   `builtBy`, `pageLanguages`, `notJudged`, `changes` (NO_DIRECT_EDITS), `readOnly`. Under the answer cap (scope.mjs AIM):
   findings cut with `findingsNotListed`. Metadata only: no text of the report is quoted (lengths and counts, as the
   rules do); nothing written; Microsoft's validator not run (the lens asks another question; check_report without lens
   still does).
2. **`mcp/server.mjs`**: check_report's input gets `lens: z.enum(['arabic']).optional()`; with it, the lens answers.
   Without it, check_report is exactly as before.
3. **`mcp/lib/agent-text.mjs`**: one sentence, `ARABIC_LENS`, in check_report's description and as one line of the
   instructions (within INSTRUCTIONS_MAX 2,200: the other lines said in fewer words, every phrase a test reads kept).

4. **Not changed**: report-rules.js and report-a11y.js (used as they are: no website suite or .min.js moves),

## Decisions I made
- **One module, `mcp/lib/arabic-lens.mjs`, not new rules in report-rules.js.** The brief names report-rules.js for the
  bidi rule, but that rule lives in `mcp/lib/terminology.mjs` (isolateLatin), and the lens's words come from the twin
  (report-mirror.js's KIND_WHAT, arabic-twin.mjs's MATRIX_SAID), all MCP-side; check_report's default answer stays
  exactly as it was, so no suite or website page moves. The existing rules (RTL_MIRROR, A11Y_TAB_ORDER) run as they are,
  every page read right to left; the lens only selects and words them.
- **Four kinds of fix:** the brief's two (a DataArcus call; "Power BI has no setting") plus `desktop` (a setting the user
  changes in Power BI Desktop: the only honest fix for an Arabic page of a report DataArcus did not write, since the twin
  of an Arabic page would mirror it back) and `model` (the calendar names: a model step). A "none" fix names DataArcus's
  alternative when there is one (the mirrored waterfall).
- **The twin (c) keeps the calendar line**: its month names are the model's English values until the user applies the
  Arabic calendar script; the twin's own `cannot` says so ("data values ... a model step"). C1 allows that one line and
  every "no setting" line, nothing else.
- **The validator is not run with the lens**: it answers another question (check_report without lens still runs it).
- **One finding per page and rule, with a count**, so the answer stays short (findings cut to the cap with
  findingsNotListed; the summary keeps every count).
- **Time is told by the mirror itself** (mirrorVisual in memory with timeRightToLeft true and false: different query =
  a time category), not a copy of its name test: report-mirror.js is M1's file and was not touched.
- **The page's language**: S1's pageLanguages; a page none of its ways tell takes the language most pages have, else
  English (S1's fallback is the report's language, which the lens does not compute separately).
- **Instructions**: rule 8 is the short form; the first line's "in one working folder" went (every tool's path text
  still says the working folder) and rule 1's "Call ... one within the limits gets" became "gives".
- Shared files touched, one line each: `mcp/lib/check-report.mjs` (two functions exported, no change), `mcp/server.mjs`
  (check_report's lens option and its branch; two imports), `mcp/lib/agent-text.mjs` (two sentences, rule 8, two lines
  shorter), `mcp/README.md` (check_report's row), `mcp/package.json` (the suite at the end of `npm test`), `mcp/WORK.md`
  (one bullet). Not touched: report-mirror.js and the twin (M1), CI and the README's setup section (P1), any assets/js file.
