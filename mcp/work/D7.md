## What was looked at (before any code)
- Microsoft's capabilities data (`@microsoft/powerbi-core-visual-schema`, the version `mcp/package.json` pins):
  - waterfallChart: roles Category, Breakdown, Y, Tooltips; `sentimentColors` increaseFill / decreaseFill / totalFill /
    otherFill (no default values in the catalog); `valueAxis.totalsEnabled` (the Total column on/off);
    `categoryAxis` has NO invertAxis (D1's finding, again).
  - columnChart (the stacked column chart): no total-column or "add a category" option. `totals` is the stack's total
    LABEL above each column, not a column; `legend` has no per-series switch (show, position, title, font only);
    labels have per-series `showSeries` and `valueCustomFormatString`; no per-series tooltip switch.
  - Microsoft Learn (report themes): "good, neutral, bad: these properties set the status colors used by the waterfall
    chart and the KPI visual". DataArcus's theme writes good, neutral and bad (design-engine.js buildTheme). The
    Total's default colour is not documented and not in the catalog: measured on the laptop only.
- The English waterfall (pbip-page.js gallery block) writes no sentimentColors: its increase/decrease/total colours are
  the written theme's good / bad / (Power BI's own total rule). D1's mirror writes rise = the theme's good, fall = bad.

## The Total column: decision (c), no faithful way
- (a) Power BI's own mechanism on a column or combo chart: none in the catalog (above).
- (b) a small axis table as a TMDL script (lib/model-script.mjs): the steps + "الإجمالي" as members, the chart's
  category bound to the new table. Rejected: a visual bound to a table the model does not have yet is Power BI's error
  ("Something's wrong with one or more fields") until the script is applied, which the brief forbids ("until applied the
  chart must still show the steps without the Total, not an error"); one written visual cannot bind the model's column
  before and the axis table after. A two-step flow (apply, then build again) is not "the same design" for the person.
- And the legend: a stacked column chart's legend lists every Y series, the invisible base included (no per-series
  switch); Power BI's waterfall legend is Increase / Decrease / Total. With a fifth series for a step that crosses 0 it
  would list up to five entries. So the legend stays off in "mirror", and the base shows in the tooltip («القاعدة»).
- So: **(c)**. The same design mirrored cannot be written: no Total column, no Power BI legend, the base in the tooltip.

## The switch
- `waterfallRtl: "mirror" | "native"`, one constant `WATERFALL_RTL_DEFAULT = 'native'` in assets/js/visual-gallery.js
  (shared: the writer, the twin and the MCP read it; flip it to 'mirror' for D1's look). Default "native" because of (c).
- "native": in a mirrored right-to-left report the waterfall is written exactly as the English one: Power BI's
  waterfallChart, its sort as the English (Ascending in time), no switchAxisPosition (the value axis where Power BI
  puts it), no categoryAxis.invertAxis; the plan and the notes say "the waterfall reads left to right, as Power BI draws
  it". The twin keeps the original's waterfall as it is (its place mirrored only).
- "mirror": D1's stacked column chart, plus: the falls labelled negative like the English (the fall measures' format
  string: the measure's negative section, else "-" + its format, else "-#,0"); colours: rise and fall = the theme's good
  and bad (as the English waterfall's increase/decrease), the twin keeps the original waterfall's own sentimentColors.
  No Total column, no legend (said).
- Pinned: REPORT_LOOK (plan_layout and create_report), LOOK_DEFAULTS; create_arabic_twin's own input, pinned by its
  plan (another value with the planId: refused, nothing written); on the approval page ("Waterfall, right to left").
