## Decisions I made
- The whole untrusted-text screen moved with shownName: it is pure and only the name policy uses it (screenWhy,
  readsLikeInstruction). model.mjs no longer imports tool-names.mjs.
- modelOf moved to model-metadata.mjs (the metadata needs it; model.mjs importing it back keeps one direction, no
  cycle). model.mjs still has it in scope, so the V-rows mutant's edit (it injects modelOf into summary) applies.
- summary (read_model's table list) stays in model.mjs: the brief names column types and KPIs only; its S-suspicious
  and V-rows mutants stay unchanged. A later job may move it with scope.mjs's fullAnswer.
- The 9 S-* screen mutants point at `MN` (model-names.mjs) and R-kpi-quoted at `MM` (model-metadata.mjs); the edit
  strings are byte for byte the old ones. No expected number changed.
- The error answers are asked in a child process with its own working folder (twin, a plain model, a link): an answer
  lists the models there in the file system's order (12 at most), which differs between Linux, macOS and Windows; the
  list is sorted before it is recorded. The order (discovery) is model.mjs's and did not move.
- The link is a junction on Windows (no rights needed); if a machine refuses a link, E3 records that and C1 skips it.
- The new files sit in tests.json's "everything" list beside model.mjs (the screen is safety infrastructure).
