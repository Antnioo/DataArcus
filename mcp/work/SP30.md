## Interfaces
- **field-catalog.js (`DAFieldCatalog`)**, pure: input the readers' tables (or a model.bim's JSON), output the fields.
  `fromTmsl(json) -> tables`, `relsOfTmsl(json) -> [{ fromTable, toTable, both? }]`, `clean`, `markCalendars`,
  `catalog(tables, modelTables?) -> { measures, columns, hiddenMeasures }` (the Field typedef at its top), `fieldOf`,
  `measureOf`, `measureCard`, `isPercent`, `reached(tables, {t, m}, rels) -> Set`, `readTables`, `reachTable(table,
  {relationships, modelTables}) -> { table, notReached }`, `langOf`, `langsOf`, `twinsOf`, `fieldKey`, `exprOf`,
  `metaOf`, `isDateTable`, `nameLike`, `sortColumnFor`, `dateColumnFor`, and the shape rules the ranking shares (CORE,
  argsOf, inlineVars, valueKey, splitName, sortKind, SORT_BY, FAMILY, family). Requires field-meaning.js only. Its one
  state is the META side table (and REACH, keyed by the caller's options): one instance, read by the ranking.
- **field-suggest.js (`DAFieldSuggest`)**, pure: `rank(tables, nKpis, opt) -> { choices, notes }` (choices: the picked
  fields; notes: language, noCategory, excluded, axisBy, calendarNames, formatsMixed, calendarSwaps, noRelatedCalendar,
  noRelatedCategory, slicerPool, catPool, skipped, why, whyNotListed, statsNotInModel, in that order), `counts(tables,
  names?, opt?) -> [Field]`, `statsOf(tables, stats)`. Requires field-catalog.js only; no random source, no clock.
- **pbip-bind.js (`DABind`)**, orchestration: the browser input's forwarding (model-import-browser.js with its
  readers), `build(choices) -> binding`, `suggest = Object.assign(build(rank.choices), rank.notes)`, the picker's
  forwarding, `connection`, `mapFields`, and the same 28 exports as before (the moved ones are the same functions).

## Decisions I made
- `build` stays in pbip-bind.js (the map leaves it "builds binding" there); so rank returns `{ choices, notes }` and
  never calls build: field-suggest.js has no binding and no cycle. The notes keep the old key order, so the answer's
  JSON is byte-identical. `!out.date` became `!ch.date`: build's date is null exactly when the choice is empty.
- `statsOf`, `byLang` and `langNote` went to field-suggest (only the ranking reads them); `isPercent`, `measureCard`,
  `fieldKey`, `langsOf`, `twinsOf` and the reach to field-catalog (metadata rules). pbip-bind re-exports them all.
- Both new files are required eagerly by literal path (the MCP's packaging stages what it can name; the website
  loads them before pbip-bind in theme-generator.js's loadBind): field-meaning, tmdl-model, field-picker-ui,
  model-import-browser, field-catalog, field-suggest, pbip-bind. New stamps 20261104sp30a (A) and 20261104sp30b (B)
  for pbip-bind, the new files and theme-generator.min.js on its three pages (the Arabic copy rendered again).
- Source-reading pins: v029p (TIEBREAK_WORDS, the Field typedef), v029k (no PCT copy) and sq13 (no `|| 'string'`) now
  read pbip-bind.js with field-catalog.js and field-suggest.js (the same checks and counts, still guarding all three).
  v029e A1-8 (TMDL through tmdl-model) and website pbip's relsOfTmsl pin still read pbip-bind.js, unchanged.
