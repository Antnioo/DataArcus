sees each red before / green after.

1. **T-1** the approval page's file list (`lib/approval-window.mjs` `filesHtml`): a summary by kind first, in words
   ("1 report: 4 pages, 38 visuals, 2 bookmarks, 4 phone layouts; 1 theme; 1 script"), the file(s) the person asked
   for named on top (a script, a theme file), the full list folded under one closed `<details>` (still every file, still
   grouped). The count is the plan's own `outputs` list, which is what the write writes (test: the count on the page =
   the files the write added on disk, twin and report).
2. **T-2** a report path that misses (`lib/read-report.mjs` `locate`, used by read_report, create_arabic_twin,
   check_report, the redesign and the native copy): when the path is not there, search the working folder (inside
   `DATAARCUS_ROOT`, metadata only: names of folders and `.pbip` files, depth 4, at most 4,000 entries, links not
   followed) for a report of that name (`.pbip` / `.Report`, with or without the extension) and answer
   `Did you mean "Sales/Twin Sales.pbip"?` (one hit), or name up to 8 hits, or up to 8 reports found when no name
   matches; the message says to retry with that path, never to ask the person. The model path already resolves a
   name across the working folder (`model.mjs` `byName`, NO_MODEL_NAMED lists the models): nothing to change there.
3. **T-3** "0 problems Power BI Desktop would show, 3 more worth a look" (`assets/js/layout-check.js` `checkProject`
   gives `worthALook`): the approval page lists each item in one plain line (page, visual, what), or says
   "no action needed" for a note that needs none; plan_layout's answer carries the same lines (`check.worthALook`).
4. **T-4** "TMDL script" / "the user applies it in TMDL view": one shared text (`lib/plain-words.mjs`): what the file
   is ("a small text file that adds ... to your model; DataArcus never changes your model itself") and the 3 steps
   (Power BI Desktop > TMDL view > paste the file's text, Preview, Apply), on the approval page (whenever the plan writes
   a `.tmdl`) and in every plan answer that writes one (`Plans.proposal`: `scriptIs`, `howToApplyScript`).
5. **T-6** the page, the plan and the write answer agree. Found in the code before writing: (a) every new report
   writes one `<slug>-background.png` per page, a blank see-through 1-pixel image when no picture is given

   "true"; (b) a redesign copies the original's theme file and images as they are (with the theme changes listed, if
   any), so "no theme file of its own" sat above the original's theme. Fix: the file list names a blank background
   "Page background (blank, see-through: the page shows the theme's colour)"; the write answer says the same; the
   redesign's sentence says the theme and images listed are the original's, copied. Test on the redesign and the
   exec-report cases compares the page's kinds with the plan's and the write's sentences. The judge's "unplanned
   slicer": checked against the plan's text (the Fields section shows the planned slicers; a slicer the artifact adds
   beyond them must be on the page too), fixed if the text omits it.
6. **T-7** internal inputs: the Inputs section in plain words (each known input by its meaning: "Findings listed per
   check, at most 15", "Week starts on Sunday"), the raw inputs behind a closed "details" fold; options the report
   doesn't use left out (the twin's waterfall direction only when the report has a waterfall, the picture pages only
   when it has one); a redesign's move said in words ("4 wider: 704 x 640, same place"); "fingerprint" replaced by
