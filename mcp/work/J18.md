## Decisions I made
- Memory: confirmed terms are kept in the MCP's memory for the session only (confirm-memory.js's term records,
  {modelKey, objectKey, scope, evidenceHash, dependencyHashes, alias, decision}); nothing is written to disk. A file
  next to the model would be a new write and a new PRIVACY sentence (R7's re-read): left for the owner's go.
- Confirmed = answered by the person: a term given in displayNames / terms, or declined (the model's own name). A draft
  of the fixed list approved only with a whole plan stays a draft next time ("never silently translate").
- modelKey = the model folder's real path + its tables (another folder with the same tables is another model).
  Evidence = kind, type, description; dependencies = DAX, source column, sort-by column.
- Isolation applies to the names a person approved (create_report's displayNames, the twin's labels and terms):
  wherever an Arabic report shows one, its Latin runs are wrapped; a run at either end of the text gets U+200F (round
  13: a title is a left-to-right paragraph). Numbers alone and {n} placeholders are not isolated; filter values and
  names are never touched. (First built for every mixed text: the full run's test.mjs failed 3 checks, e/h and P3-2,
  "عدد ⁨Order Id⁩ (⁨Region⁩)": that changes what Desktop shows on titles that keep a model name in English, outside
  this job's terms. Narrowed; see "Decision needed".)
- Test changed on purpose: test-0.2.9i.mjs P3-2's "English names in an Arabic report" now uses its own copy of the model
  (`i-ar-en`). In the same session the test had just approved Arabic names for `i-ar`, which are now that model's
  confirmed terms and are reused (the feature); the check's intent, a model with no Arabic names, is kept.
- The twin: a term labels every header of its field and wins over a label given for that header (listed in
  labelsNotUsingTerm); a title or alt text with a label of the person's own is kept and listed when it says the field
  otherwise. An English name two fields share with two different terms derives nothing.
- askNext asks drafts first, then fields with no Arabic; the plan still gets its id (as before), the sheet says what is
  draft or kept.
