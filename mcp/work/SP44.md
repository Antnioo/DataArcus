## Decisions I made
- The view gets `{ plan, show }` (and `decided` for the done page), not the window record: the record held the secret,
  and the map says the view receives a prepared disclosure model. askPage and donePage read only those fields, so
  every page is byte for byte the same (sp44 H1, L7; sp23 H1).
- The secret moved into approval-http.mjs whole: made (issue), looked up (bySecret), given as a link (linkOf) and
  forgotten (revoke). The window record no longer has a `secret` field; http keeps a second map, planId -> secret, so
  the window never holds it. issue forgets an old secret of the same id first (it never has one today: a window is
  made once and close revokes; this keeps one link per plan by construction).
- The decision: the HTTP side alone calls it (after the Host, secret, expiry, method, Origin and "not decided yet"
  checks); what a decision does (w.decided, onDecide, the waiters) stays in the window's open(), as the map leaves the
  lifecycle there. `w.seen = true` became the window's `seen(w)` hook, called at the same point. The first open's
  hooks are kept by listen, as the first open's decide was before.
- The browser launch and node:child_process stay in approval-window.mjs (the brief), so write-gate's entry
  `lib/approval-window.mjs: child_process x1` is unchanged.
- sp44's V1 pattern was narrowed in the view's commit (`.origin\b` not `\borigin\b`: the page's own
  `content="same-origin"` meta matched); no record changed.
- The guards that read moved text as source read the new files too: 0.3.0-claims (A2-A2 and both per-file lists),
  release-text, fx3 (C2), r5-answers (F04-8 `writesNote(`); the mutants A-writesAr-match, A-writesAr-esc, A-pair-lang
  point at approval-view.mjs (edit strings byte for byte), and the unused `AW` name went (lint). tests.json: both
  files beside approval-window.mjs in "everything".
