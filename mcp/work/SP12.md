## Decisions I made
- ESCAPES (the run-time `esc` node's table) went with the expression tree, not with svg-escape.js: the evaluator and
  the DAX printer both read it, and it is what the tree does when the measure runs; svg-escape.js holds what the
  compiler writes as fixed text. Both files stay independent (neither requires the other), so the load order between
  them does not matter. The table is now frozen (each pair too) so no caller can weaken it; the values are the same.
- N and both APIs are frozen: nothing added to them before; a frozen object cannot be patched to add an operator.
- The escaping code moved character for character (no regex rewritten); attribute and literal escaping stay separate
  functions; `color` keeps its black fallback for anything not #rrggbb or none.
- The designer's own copy of the BLANK rules (`evalValues` in svg-kpi-designer.js) is left as it is (not this move).
- The website record keeps the canvas's layers and viewBox, not its width and height (the editor's zoom, from the
  page's width); W3 reads the scripts' document order (deferred scripts run in it; the network fetch order varies).
- A literal 123456789012345678 in the suites is written 123456789012345680 (lint: the same double; same records).
- New stamp `20261103sp12` for svg-escape, svg-expressions and svg-kpi-compiler.min.js (the two designer pages).
