## The plan (written before any code; LAYER in brackets)
1. **[report writer] `assets/js/report-mirror.js`** (new shared engine, Node and browser, no dependencies; like
   `report-rules.js` no page loads it yet, so no `.min.js`). Pure JSON in, JSON out:
   - Positions: `x' = W - x - width`, W = the page's width for a top-level visual or group, the parent group's width for
     a visual inside a group (PBIR positions in a group are relative to it), so nested groups mirror exactly; y, z,
     sizes, `tabOrder` unchanged.
   - Column, line, area and combo charts (and stacked/100% kinds): `valueAxis.switchAxisPosition` true; the order
     reversed by the sort: an existing sort's direction flipped (a chart sorted by its value: the largest at the
     right), else Descending by the category (Aug ... Jan, January at the right). With `timeRightToLeft: false` a
     time category (a hierarchy level, or a column of the date table or named like a date part) keeps its order.
   - Bar (clustered, stacked, 100%): `valueAxis.invertAxis` true (bars from the right),
     `categoryAxis.switchAxisPosition` true (names at the right); top-to-bottom order kept.
   - Legends: left and right swapped (Top/TopLeft -> TopRight, Left -> Right, Bottom/BottomLeft -> BottomRight, the
     right ones to the left ones, centred ones kept); a chart with a legend role and no position gets TopRight.
   - Table (`tableEx`): its columns in reverse order (Power BI does not mirror a table); a text column (a plain column
     projection) right-aligned with `columnFormatting` (selector `metadata: queryRef`, `styleHeader`, `styleValues`,
     `styleTotal`; this repo's round 0 and round 11 proof); measures keep their alignment. Matrix: its values reversed
     (its rows, a hierarchy, keep their order). New card (`cardVisual`) with several values: reversed, value
     `horizontalAlignment` right in the default entry.
   - Text: every text box paragraph `horizontalTextAlignment` right (centred kept); a visual title's `alignment` left or
     unset -> right (centred kept); a button's text alignment left -> right and its icon left -> right (not in the
     labs: on the laptop's proof list).
   - Positions rounded to 0.01 (never -0).
   - Position only (nothing in them has a side, or Power BI has no setting): card, new card, multi-row card, KPI,
     gauge, donut, pie, funnel, treemap, maps, image, shape, slicer, **page navigator** (no order setting: the first page stays at the left; proven round 2), and **custom
     visuals** (their settings left as they are; listed).
   - Navigation and bookmarks: page names (ids), visual names, `visualLink` targets, `navigationSection`, bookmark
     names and their visual references are never changed.
   - `mobile.json` (the phone layout, one column) is copied as it is.
2. **[MCP tools + agent instructions] `create_arabic_twin`** (logic in `mcp/lib/arabic-twin.mjs`; `server.mjs` only
   registers it; a `twin` plan kind in `plans.mjs` that allows only this tool and carries the approved labels):
   - Without planId it writes nothing and answers the PLAN: the twin's names ("<name> AR.Report", "<name> AR.pbip",
     next to the original, same model), the pages, per page what mirrors and how (counts per kind), **what cannot**
     (custom visuals, matrices, the page navigator's order, the phone layout, and Power BI's own words: "All",
     "Total", "(Blank)", month and day names from the model, number formats), and every text of the report (page
     names, titles, text boxes, buttons, field names, bookmark names) with a `draftArabic` from the fixed glossary of
     `arabic-names.mjs` where every word is in it, else null: Claude drafts the rest under the Arabic voice rules and
     shows them as DRAFTS; nothing is translated silently. Texts that read like an instruction are withheld (kept as
     they are). The labels the user approved are passed as `labels` (`{ id: text }`); the plan id is for exactly
     those labels.
   - The Arabic month column: when the model has one date table (dataCategory Time, or one table named like a
     calendar with a date column) and no Arabic month name column, the plan offers a TMDL script adding
     `Month Name (Arabic)` (SWITCH on MONTH of the date, sorted by the table's month number column, or a hidden
     `Month Number (AR sort)` written with it). Written next to the project only after go; applied by the user in TMDL
     view; never applied by DataArcus.
   - With an approved planId: writes the new folder and .pbip with `wx` (never over anything; refused when the name is
     taken), a new `.platform` logicalId and displayName, the same `definition.pbir`; the original is only read.
   - Limits as check_report's: no links followed, 8 MB a file, 12 levels, 20,000 files.
3. **[tests] fixture `mcp/fixtures/twin-project/`** (made up, no employer data): "Twin Sales" with a model.bim
   (Sales, Calendar marked as date table with Month Number), 2 pages (1280 x 720 and 1920 x 1080) and a tooltip page;
   a group with a nested group; bookmarks; a page navigator; page buttons (`PageNavigation`) and a bookmark button; a
   table; bar, column and line charts with a legend; a slicer; a text box; a custom visual. Original is
   validator-clean first.
   New `mcp/test-0.3.0-twin.mjs` (run by test.mjs and alone), written first.

### The one decision needed
**Time right to left by default?** The labs treat it as a design choice (plenty of Arabic dashboards keep time left to
right) and suggest mirroring as the default. Built that way (`timeRightToLeft: true`), with the plan asking the user each
time. Owner: keep the default, or default to left to right?
