## Interfaces
- `health-rules.js`: `runRules(input)`. Input (one frozen object): `{ M, IX, report, used, vis, broken, styleByMeasure,
  userTables, autoDateTables, allMeasures, mQueries, chainDepths }` (the normalised model and its frozen index; the
  report's reading or null; the nodes reached; the visuals per measure and column; the report's broken references;
  daxRefs's style per measure; lists of M; the Power Query queries; each measure's chain depth). Output:
  `{ findings: [{ id, items }], skipped }`, in checking order, no score. Also `RULES`, `BPA_URL`. Requires the parser
  (tokenizeDax, daxCode) and the index (K) only.
- `health-confirm.js`: `pleaseConfirm(M, { userTables })`. Input: the normalised model. Output: `[{ id, obj, message:
  { en, ar }, evidence, format?, relationship?, table? }]`, asking order; no score, no require, never writes M.
- The engine: `analyze(modelJson, report)` builds M, IX, the graph (deps, used, usedBy, depth), the report's use and
  broken references and the M queries, calls runRules, weighs the findings (SEV, CAP, SCOPE, scoreFrom), sorts them,
  calls pleaseConfirm and returns the same object as before.

## Decisions I made
- **health-rules.js is 620 lines, not under 600:** 210 are the catalogue (37 rules' bilingual texts and their cited
  sources), 370 the checks the catalogue names; the map puts both in one file ("declares rules", "rules return
  findings"). Under 600 would mean a fifth file (the catalogue alone, or the DAX shape readers isText, filterOverTable,
  predKind, countRoot) the map does not name, or joining lines. Left for the reviewer (Seen, not in scope).
- The score stays in the engine: SEV, CAP, SCOPE, the penalty and share per finding and scoreFrom (the brief: rules
  return findings; the questions apart from the score). runRules returns `{ findings, skipped }` only.
- The engine now lists the Power Query queries and counts their sources (stats) itself, before runRules; the rules
  read the list. The measure-chain depth is computed by the engine in the rules' own order (allMeasures) and passed
  as `chainDepths`, so the memoised walk (its hidden state) stays in the engine; the values are the ones the rules
  computed (records unchanged, including the cycle in E1).
- The input to runRules is frozen (Object.freeze, shallow; the index is frozen by model-index.js). H2 also proves the
  whole input (its Maps and Sets) is unchanged after the call, and a second call gives the same output.
- **The worker keeps the stamp 20261103sp15** where it is started (assets/js/model-health.js and theme-generator.js):
  the brief keeps me out of model-health.js, and one stamp per path means theme-generator.js keeps it too. The worker's
  file changed (two more importScripts names); main never served that stamp (check-min passes against main; 0.3.2 is
  unreleased), so no browser holds an old copy under it. The new files and the engine take `20261104sp27`.
- sp15's three models (B1-B3) moved to fixtures/health-models.mjs, unchanged (sp15 19, its records unchanged).
