## What changes for the user
Nothing while the switch is off (the default): the 11 tools, their texts and the instructions are 0.3.0's. With
`DATAARCUS_EXPERIMENTAL_RENDER=1` on Windows with Power BI Desktop: `render_report` on a written report opens Desktop
on a copy with made-up rows for 30-120 s (estimate), and the AI gets one image a page, the boxes, what the images can't
tell and how to look; fixes come back as a new plan to approve. When the model's DAX holds constants, the first call
lists them by name and asks "stub" or "keep" before Desktop starts.

## Decisions I made
1. Registered from its own module (`lib/render-tool.mjs`), loaded only with the switch: `scripts/test-site-config.mjs`
   counts `server.registerTool('...'` in server.mjs to check the site's "11 tools"; the site stays true while the tool
   is off. When the owner says go, the reviewer moves it into server.mjs and the site, README, PRIVACY and beta page
   go to 12 together.
2. No approval plan for a render: it writes nothing in the working folder (the copies are in the OS temp folder and
   deleted, as J14's validator copy). Its description says to ask the user before the first render (Desktop shows on
   the screen). The DAX-constant choice is a separate, explicit question, never defaulted by the tool.
3. Temporary folder: the OS temp folder (`dataarcus-render-*`), like J14 (R1's open question; the draft names it for the
   owner).
4. The DAX form by default (round 2, measured: a DATATABLE opens with its data; a Power Query table opens empty).
5. A constant is a number other than 0 and 1, or a text other than "" or a format pattern (`"#,0.0"`, `"dd MMM yyyy"`,
   `" - "`); comments and digits inside names are not. A field parameter's texts are names (kept, not listed). Calculated
   columns are all listed, also those whose rows are made up (a little more than needed: the safe side).
6. Magnitude: a unit of 1,000 or more makes a row value scale/1000 to 5 x scale, so a 120-row total shows in that unit
   ("120M"); the column's own format first, then the largest of the measures that name it, then `magnitude` (only when
   the user said it). Whole-number columns are not sized.
7. Pages are captured by id through Microsoft's preview (`--page <id>`, one page a call, `--scale 1`; not
   `--all-pages`: the lab's REPORT_DIR_REQUIRED on generated projects); a page it can't capture is answered "not
   captured" with its error code, the other pages go on. A retryable answer (Desktop still opening the report) is asked
   again within the wait. A capture whose pid is not the Desktop DataArcus started stops the render, nothing returned.
   Each preview call is checked before it runs: only `--host desktop` on the shadow's own .Report folder; never
   `--host service`, `--group`, `--dataset`, `--close`, `--reload`.
8. Close: `taskkill /PID <pid> /T /F` (its tree: msmdsrv goes with it), only after checking that the process's command
   line names our project file; never by name. A Store Desktop that starts again under a new pid is found by its
   command line naming our project, never another Desktop.
9. A dialog = the main window disabled or a Win32 dialog (`#32770`) of our process: the render stops and clicks nothing.
10. The image is Desktop's capture of the page through the bridge (it may show the Filters pane, R1); the window is
    never moved or activated.
11. Box lists carry type, kind and place, never title text (as read_report: a static title is not returned; the image
    shows it).
12. The learning hook (S2-6) is `scoreRender` in the answer as `learning: { score: null, why }` until the laptop
    measures boxes in an image.
13. The settle waits are chosen, not measured (90 s first page, 30 s for each next page, a capture every 1.5 s; each
    capture is a run of the preview command, about a second or two of its own): the laptop measures them first.

## Seen, not in scope
- The images may be large: a page capture at scale 1 is a few hundred KB of PNG, about 1.3x that in base64, one a page
  in one answer; an MCP client's limit on an answer's size is not known (the laptop sees it).
- Microsoft's preview command is a public preview ("the CLI command surface ... may change"): its JSON envelope and the
  Desktop host's attach rules are read from 0.5.0's code; a version bump in `mcp/package.json` needs the fake preview
  checked against the new one.
- Packaging (the extension and the plugin) carries every file of `mcp/`; when the tool leaves the switch, check that
  `lib/desktop-render.ps1` is in the package and that PowerShell's execution policy (an organisation's AllSigned)
  doesn't block `-ExecutionPolicy Bypass` for a script file.
- The fixtures' models have no DAX constants (twin, arabic, health: 0): the constant question is proven by the tests'
  made-up model only.
- Pages are captured by id, so the Arabic page names are not matched; whether the bridge's capture of a right-to-left
  page is mirrored as Desktop shows it is for the laptop.
