Builder, 25 Oct. Branch `chore/0.3.1-lint-coverage` from `origin/integration/0.3.1` (df778b6). Pushed only; no PR, no
merge. The owner, 25 Oct, after an outside review ("linting and static checks for the core JavaScript", "coverage
reporting to identify untested branches"): "make it all in 0.3.1". No behaviour change except a listed, trivially safe
fix. GC's files are linted and their findings listed, never changed (`assets/js/calendar-generator.js`, `gulf-dates.js`,

section (below the rule) is the Q1 of 0.3.0, the large-model caps: the ID was reused, its file kept (as G1 did).

## Plan
1. This plan, pushed first.
2. **ESLint, one flat config at the repo root** (`eslint.config.mjs`), `eslint` and `globals` pinned exactly in the
   root `package.json` (devDependencies), `npm run lint` there. Root, not `mcp/package.json`: the MCP stays
   self-contained and its package ships no lint tool; one config covers both trees; the website-checks job already
   runs `npm ci` at the root. Files: `mcp/**/*.mjs` (not `mcp/schemas`, `node_modules`, `fixtures`) and
   `assets/js/*.js` (not `*.min.js`; not `assets/js/translations/`: 39 data files, `window.x = {...}`, no code).
   Rules: only those that find bugs (the brief's list: no-undef, no-unused-vars with args none, no-unreachable,
   no-dupe-keys, no-dupe-else-if, no-self-assign, no-self-compare, no-unsafe-finally, no-unsafe-negation,
   no-cond-assign, no-constant-condition with loops allowed, no-fallthrough, no-sparse-arrays, use-isnan, valid-typeof,
   no-redeclare, no-shadow-restricted-names, no-loss-of-precision, no-async-promise-executor, require-yield,
   getter-return, no-import-assign, no-unused-private-class-members), all errors; no style rule, no Prettier.
   Globals: node for `mcp/`; browser for `assets/js/`, plus `module`/`require` for the UMD engines (the files that
   assign `module.exports`, found by the config from the files, so a new engine needs no edit), worker globals for
   `model-health-worker.js`, and the site's own `window.*` globals that one file sets and another reads, named.
3. **Run it**; every finding: a real bug -> listed here with file:line and a proposed fix (the reviewer decides); a
   trivially behaviour-neutral one (an unused variable or import) fixed in its own commit, each listed; a false
   positive -> a precise config entry or a one-line disable with why. Counts per rule before -> after. Then a proof
   that `npm run lint` fails on a new bug (a scratch file with an undefined name and a duplicate key, removed).
4. **CI**: `npm run lint` as one step in `website-checks` (after Install). A `coverage` job (Linux, not a gate, not
   needed by any required check): c8 (pinned in the root `package.json`) over `cd mcp && npm test -- --keep-going`,
   the text summary (per file: lines and branches %) written to the job summary and uploaded as an artifact.
5. `node scripts/check-result-lines.mjs`; the full `cd mcp && npm test` once at the end; if an `assets/js` file
   changes: `npm run build:min`, `npm run check:min`, its pages' `?v=` stamps and the website suites it touches.

## Decisions I made
- The 10% margin is the test's line: an answer at 36,000 or more fails, and so does any answer the backstop had to cut.
- Cut where the list grows (health items, twin texts, redesign lists, read_model tables, check_report findings); safety
  statements and refusals are never cut. The twin's notTranslated (said before the go) is cut only if the texts alone
  can't make room (never in these runs); the approval window shows it whole.
- `only`, `textsFrom`, `redesignPages` change what an answer lists, never the plan, the pins or what is written.
- Indentation dropped above 34,000 rather than cutting plan_layout's statements (each feature's sayInPlan).
- The Ramadan page: the large model has no Gulf calendar, so grain "hijri" is refused (as it should be: add the calendar
  first); the run uses grain "gregorian", scope "all" with the date the report follows: the date questions answered.
- The theme in the suite uses the default font: with Tahoma every report gets a "can break" (below).
