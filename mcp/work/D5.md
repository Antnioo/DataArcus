## CHANGELOG line
- D5: the approval window's preview draws what Power BI Desktop draws: every title as the report create_report writes
  it (a Top N title by the text its measure shows, no "(2)"), a title or table header marked cut only when the
  writer's and check_report's own measure says so, and each slicer with its header.

## The problem (the laptop, 0.3.0-rc.2, Desktop 2.159, 1366x768; large-synthetic, lang ar, focus "Web Orders")
1. «مقطوع» on titles Desktop draws whole (T1a: the table; T1b: the line chart and the table).
2. Page 2's Plan Group bar title ends with "(2)" in the preview only.
3. Page 2's three slicers are blank boxes; Desktop shows their headers («السنة», Coupon Region, Plan Group).

## Causes (found on 97542c0, before any change)
1. The marks are not title measures at all: they are J12's own rough rules in `page-preview.js` `check()`, which no
   other part of DataArcus uses: (a) a table is "cut" when the SUM of all its headers' widths (+24 each, every
   projection, even the 0-wide one) passes the table's width less 36 (exec table: "need 1000, has 891"), while the
   writer gives every column its own width and check_report's TABLE_HEADER_CUT (report-rules.js `tableHeaders`, the
   measured rule of B-173) finds every header whole; (b) a line chart is "cut" when its category labels may slant
   (ops line chart, Month Short: "51 a month, 66 needed"): slanted labels are not cut, and check_report has no such
   finding. The tag sits at the box's top corner, over the title, so it reads as "the title is cut". The renderer
   also lays titles out with its own wrap (split on any space, its own room) instead of the writer's `titleFit`.
2. A chart cut to its Top N is titled by a report measure. Its NAME must be unique ("Title: X (2)" for the second
   chart with the same title); Desktop shows the measure's VALUE, the plain title "X" when every category shows.
   `fromFiles` took the name. (The preview is also built from planLint's own build, not the exact artifact #69 checks.)
3. A slicer's header is not a title (`title.show` is false; Desktop draws `header`: its text, or the field's display
   name); `fromFiles` read no header and `render` drew none.

## Plan (fix at the cause, in the shared code)
- `assets/js/page-preview.js`:
  - titles: a Top N title measure is read from `definition/reportExtensions.json`: the text its DAX returns when all
    categories show (the writer's `IF ( _s = _n, "<title>", ...)`); never the measure's name. A title is laid out with
    the writer's own `titleFit`/`wrapLines` (pbip-sizing.js `make`, the room the writer gives: the box less
    round(16 x page/1080) a side; the title's size and font as written or the theme's), so the lines drawn are the
    lines Desktop draws; the text-measure.js Arabic metrics as everywhere else.
  - `cut` for a title only when the shared measure says so: the writer shortened it (the text it wrote ends with "…"
    and the alt text holds more), or `titleFit` says it does not fit two lines (a title the writer did not fit).
  - `cut` for a table only from check_report's own measure (report-rules.js `headerNeed`, TABLE_HEADER_CUT's), per
    column with a set width, state `cut` ("may be cut" is check_report's note, not a cut); a wrapping header is not
    judged, as there. J12's sum of headers is gone.
  - category labels that may slant: a quiet note (grey tag, «قد تميل التسميات» / "labels may slant"), not a cut.
  - slicers: the header's text (header.text, else the field's display name) at its size (header.textSize, else the
    theme's slicer header size, else 10), drawn above the dropdown box; `header.show` false draws none.
- `mcp/lib/plan-lint.mjs` `planPreview`: takes the exact artifact's files (`a.files`) when given and draws those;
  `mcp/server.mjs` builds the preview after the exact artifact, from its files (the old build stays for a plan
  without one: no model).
- Lab page (`theme-generator.js`): the preview draws after the check's scripts load (report-rules.js is then there);
  `?v=` bumped where page-preview.min.js and theme-generator.min.js are loaded.
