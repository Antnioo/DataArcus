This updates the previous twin-fuzz lab, retaining its real plan, label pagination, approval, write, validator, repeat/permuted-page determinism and source-preservation checks. Node 24.19.0 is installed here; the product supports Node >=20.10 (`mcp/package.json:15`). No product source was edited. Temporary synthetic projects and worker outputs live inside this results folder and are cleaned after execution. No evidence JSON or model rows are retained. Only reduced failing specs are kept in cases; replay materializes their empty synthetic model in temporary storage.

Run `node fuzz.mjs /workspace/DataArcus --cases 1000 --out /absolute/path/inside/this/folder/new-run`. The default seeds start at 20261103. Four batches of 250 use two ordinary Node child processes to bound the upstream plan registry. These are script workers, not agents. ## Properties and decisions

B2 reports only new positive overlaps between original visual pairs, with a half-pixel tolerance in each dimension. Disclosed new overlaps still fail this strict property. B3 applies the 75% width and height threshold and the 60px bar/column floor only when English was at least 60px, respecting the existing plan-disclosed exceptions. The product guard is `mcp/lib/twin-pages.mjs:578-589`. D1 normalizes only `.platform.config.logicalId`, then compares independent runs and reversed page identities. P1's answer-path requirement is skipped; exact approval digest binding remains checked under S1 (`mcp/lib/twin-write.mjs:120`).

A1 computes grid edges from position, container padding and the row field's columnWidth. An absent row width counts as zero on both sides, matching the observable metadata convention in `mcp/lib/twin-pages.mjs:295-303`; Desktop's automatic width is unknown. A chart within 24px above/below a matrix qualifies when both horizontal edges lie within max(2px, one synthetic hour cell). Check the offset, source sort preservation, matching explicit grid/category sort directions and unchanged value/category axis cards and padding. Source grid sort comparison uses the matching category field. No sort/domain values are read. This is stricter than the product's 80% overlap eligibility and collision/clamp exceptions (`mcp/lib/twin-pages.mjs:307-319`). Report such exceptions explicitly, not as proof that Desktop rendered incorrectly.

F1 checks every added or resized table/matrix. Weekday matrices and their added names tables have a seven-row semantic estimate. General tables' row counts are unknown and counted as uncheckable. Estimated row height = (15.1/8)*textSizePt + 2 + 2*rowPadding. Need = (7 + one header + optional total)*rowHeight + optional 1.6*rowHeight title + max(6, container top+bottom padding). This extends the product's fit estimate (`assets/js/report-mirror.js:636-650`) with the explicit rowPadding used in its extra-row allocation (`:694-696`). It estimates scrolling risk, not pixels rendered by Desktop. An overflowing English matrix is not itself a new twin regression, but adding its names table despite that overflow is a failed fit eligibility decision.

For explicit column widths, the header estimate is TextMeasure.textWidth(English header, pt, false, Segoe UI)+12px. The product's character-weighted width is at `assets/js/text-measure.js:20-33`; header fitting is at `mcp/lib/twin-pages.mjs:323-353`. A narrow header must have wrap explicitly off or a matching headersCut plan entry. Matrix row headers use rowHeaders.wordWrap; other headers use columnHeaders.wordWrap. The 1px hidden matrix row strip is exempt. Font/theme and renderer variation remain limitations.

N1 requires added visuals to carry schema, have unique page names and appear by name or full visual path in the plan. A heatmapNames entry naming only the source matrix does not list the added visual's identifier (`mcp/lib/twin-plan.mjs:202`). A collision probe checks whether a preexisting synthetic v0Names shape is overwritten by the generated table: identifiers are constructed at `assets/js/report-mirror.js:594` and serialized by path into a Map at `mcp/lib/twin-write.mjs:47-50`.

## Coverage and shrinking

Exactly half the generated reports use the previous mixed random generator. The other half deliberately cover the 144 combinations of three canvases, 24/10 hour cells (0-23 / 9-18 domains), short/long weekday width profiles, set/absent row width, aligned/half-cell offset/wider charts, and above/below placement. Profiles describe synthetic metadata, not data rows or actual weekday values. Some repeats add row padding or a name-collision probe. Source chart geometry stays inside its page.

Each failed input/property/reason is independently reduced by page deletion, visual deletion, optional-property deletion and safe page ID normalization. Identity, field references, geometry and lab domain descriptors are protected. Every accepted reduction executes the actual flow; exact candidates share cached results. Every retained reduction is confirmed again. Minimality is relative to this grammar, not a proof of a globally minimal PBIR file. Validators operate in the product's offline skipSchema mode, and source validator codes stay visible in stats.

The six-report pilot and the interrupted exploratory campaign are excluded from final totals. The exploratory pass exposed an out-of-page wider chart in the generator; the authoritative run moved the synthetic layout inward and protected Column/Measure objects from deletion. No oracle was relaxed to hide a product failure. Pilot artifacts are not part of the deliverable.

## Formatting control

The campaign retains the generated categoryAxis.reverseOrder property, which the pinned capabilities do not recognize. It is counted in the source PBIR_FORMATTING_PROP_UNKNOWN baseline, not suppressed. Supplemental original-seed replays at 20261127, 20261175 and 20261415 use `--known-axis-control` to remove only that property. All key F1/N1/A1/M1 findings survive and these three inputs have no offline validator error codes. Use these controls for CI. The campaign generator remains reproducible as run; this control does not rewrite its measured totals. Reduced fixtures can still have source role diagnostics because optional query roles are deletable; compare the complete original control when validating a product bug.

Evidence indices follow the sorted git ls-tree en.json paths at the pinned evidence SHA. The final manifest retains path hashes rather than source directory names.
